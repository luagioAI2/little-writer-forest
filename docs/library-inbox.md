# 收件箱 —— 在 AI 会话里贴图，出一条题库题

这一页写给「想在 AI 会话里贴几张图，就变出一道题、确认后进题库」的人。

一句话说清整条路：

> **AI 会话里出题 → 写进 `library-inbox/` → 在 App 里「📥 导入题库」→ 进题库。**

中间没有魔法，也没有第二条通路 —— App 的题库存在手机/浏览器自己的
IndexedDB 里，外面（包括 AI 会话）碰不到它。**文件是唯一的桥。**

---

## 一、为什么必须是「文件 + 手动导入」

想过别的办法，都不成立：

| 想过 | 为什么不行 |
| --- | --- |
| 让 AI 直接写进题库数据库 | 题库在 App 的 IndexedDB 里，AI 会话在另一个进程，没有通路 |
| 做个「同步服务器」 | 为了偶尔加一道题引入后端，不值得；而且离线是这 App 的底线 |
| 让 AI 直接改内置题库源码 | 能行，但那要重新构建、重新打包 APK，加一道题不该动代码 |

所以选**文件**：AI 写文件，人在 App 里点一下导入。多一次点击，换来
「不联网也能用、不加后端、不重打包」。

---

## 二、两个目录，各管一件事

| 目录 | 放什么 | 谁写 |
| --- | --- | --- |
| `library-inbox/` | **待导入**的题库 JSON | AI 会话 |
| `public/photos/` | 贴的图片本体（放进 APK，离线可看） | AI 会话 |

### `library-inbox/` 的两种文件名

| 文件名 | 含义 |
| --- | --- |
| `*.json` | **定稿了**，等着导入。`npm run inbox:check` 会逐条校验，不合格就报错 |
| `*.draft.json` | **还没定稿**，闸门跳过不检。会话里改来改去的中间稿放这儿 |

所以「改到一半」和「可以导了」不用靠脑子记 —— 看后缀就知道。
`example.draft.json` 就是一份可以照抄的模板。

### 图片从哪来：两种入口都行

| 入口 | 你会做的事 | 图在哪 |
| --- | --- | --- |
| **贴图** | 直接把图粘进会话（一张或几张） | 落在 WorkBuddy 的 blob 库，文件名是 sha256 |
| **图片路径** | 给一个路径，或一个装着图的目录 | 就在你给的地方 |

两种入口都归 `scripts/inbox-photo.mjs` 管，它会：**找到图 → 编号命名 →
压到合理尺寸 → 吐出可以直接粘的 `images` JSON**。

```bash
# ① 贴了图？先看看最近落进来的是哪几张（只列，不拷）
npm run inbox:photo -- --recent 5

# ② 确认之后，把要的那几张拷进来
npm run inbox:photo -- --slug rain-campus "<上面列的路径>" "<上面列的路径>"

# ③ 有路径就直接给（多个文件、整个目录都行）
npm run inbox:photo -- --slug rain-campus "E:/photos/雨.jpg" "E:/photos/操场.png"
```

常用开关：

| 开关 | 作用 |
| --- | --- |
| `--slug <短名>` | 文件名前缀，最终是 `<短名>-1.jpg`、`<短名>-2.jpg`…… |
| `--max <像素>` | 最长边超过就等比缩小，默认 1600 |
| `--min-kb <KB>` | 单张小于这个大小就原样拷贝，默认 400（大多数截图都走这条路） |
| `--no-convert` | 只允许同格式缩放，不往 JPEG 转（截图里文字多时有用） |

**贴图为什么不能「直接拿来用」**：blob 库里存的是内容哈希，没有原名、
没有顺序线索，而且同一个图贴两次是同一份。所以脚本给你一个「最近 N 张」
的列表，你对着时间确认哪几张是刚贴的 —— **这一步别省**，贴图很容易拿错。

> ⚠️ **一条硬规矩：缩放后如果反而更大，就保留原图。**
> 不是杞人忧天 —— canvas 重编码 PNG 拿不到原图的压缩优化，实测
> 828×1792 的 PNG 缩到 739×1600 之后反而从 591 KB 涨到 680 KB。
> 所以脚本会把「原图 / 缩放·PNG / 缩放·JPEG」都算出来**挑最小的那个**。
> 宁可什么都没省，也不能悄悄把包撑大。

### 图片放哪

脚本把图写进 `public/photos/`，题里写相对路径：

```json
"images": [{ "imageUrl": "/photos/rain-campus-1.jpg", "sceneKey": "rain-window" }]
```

- **相对路径不会踩混合内容的坑**（`http://` 会被浏览器直接挡掉，只能用 https 或相对路径）。
- 代价：图片会被打进 APK。所以脚本默认会压 —— 实测一组 1106 KB 的图
  压完剩 149 KB（省 87%）。
- 不想涨体积，就把图传图床、用 https 外链，题里只写 `imageUrl`。

⚠️ **`sceneKey` 一定要同时填**：外链/本地图加载失败时会退回这张 SVG 插画。
只填 `imageUrl` 的题，图一挂就只剩一张「暂无插图」的占位画。

## 三、收件箱闸门：为什么必须跑

```bash
npm run inbox:check      # 只跑闸门
npm test                 # 也跟着跑
```

`scripts/inbox-verify.test.ts` 会拿 `library-inbox/` 里每个 `*.json`
去跑 **App 自己的 `importLibrary()`** —— 不另写一份校验逻辑，
免得两边规则漂移、同一个 bug 要修两遍。

**为什么非跑不可**：这道题一半的错是**静默的**。导进去会显示「成功」，
但内容不是你要的：

| 写错了 | App 的反应 | 人看得出来吗 |
| --- | --- | --- |
| `category` 拼错 | 整条被丢掉，**会念出原因** | 看得出来 |
| `sceneKey` 拼错 | 不报错，那张图**永远用不上** | ❌ 看不出来 |
| `focus` 写了不认识的值 | 不报错，**被默默过滤**，评分权重悄悄变了 | ❌ 看不出来 |
| `wordRange` 形状写错 | 不报错，**默默变成 `[60, 200]`** | ❌ 看不出来 |
| `minGrade` 写成 `"3"` | 不报错，**默默变成 1 年级** | ❌ 看不出来 |
| 图片条目两个字段都没给 | 不报错，**被默默丢掉**，连环图少一张 | ❌ 看不出来 |
| `imageUrl` 指的文件不在 | 不报错，退回 SVG，你以为用了照片 | ❌ 看不出来 |

右列那些，人眼在 App 里是查不出来的。所以让机器跑一遍。

闸门报错时会指名道姓，比如：

```
📄 2026-09-16-grandpa-hands.json
  × 每张图的 sceneKey 都是真实存在的插画（写错是静默失败）
     「爷爷的手」的 sceneKey "grandpa-garden-typo" 在 scenes.tsx 里不存在
```

## 四、AI 会话里的完整流程

1. **给图**，两种方式随便挑：
   - **贴图** —— 直接粘进会话，一张或几张；
   - **给路径** —— 说一句 `E:/photos/雨.jpg`，或者一个装着图的目录。

   一张图 = 一道题；几张图 = 一道连环图题（顺序就是翻页顺序）。
   顺手说一句想要的类别和年级最好，不说就按图自己判断。
2. **AI 出稿**，写成 `library-inbox/<日期>-<短名>.draft.json`。
3. **会话里改**。「引导语再短点」「改成写事」「图二不要」——
   改的是那个文件，不是聊天记录。
4. **AI 看一眼图**，给这道题配一个 `sceneKey` 兜底（挑 `src/assets/scenes.tsx`
   里 `fits` 对得上的那张）。这一步别省，它是断网时的保底。
5. **你说「确认添加」**：
   - `npm run inbox:photo -- --slug <短名> <图>` —— 图片进 `public/photos/`，
     顺便压到合理尺寸，吐出 `images` JSON
   - 文件改名去掉 `.draft`，变成 `library-inbox/<日期>-<短名>.json`
   - 跑 `npm run inbox:check`，**红了就改，绿了才算数**
6. **在 App 里导**：题库页 → 拉到最下面 → **📥 导入题库** → 选那个 `.json`。
   会告诉你「新增 N 题 / 跳过 N 题」。

导入是**累加**的（详见 `docs/library-data-guide.md`）：
同一份文件导两次不会变成两倍，id 撞车也不覆盖。**放心重复导。**

## 五、字段速查

完整字段说明在 `docs/library-data-guide.md`，这里是出题时最常动的几个：

| 字段 | 必填 | 取值 |
| --- | --- | --- |
| `title` | ✅ | 题目标题 |
| `category` | ✅ | `scene` 写景 / `person` 写人 / `event` 写事 / `object` 状物 / `imagine` 想象 |
| `lead` | | 一句话引导，**用孩子的口吻**，像在跟他说话 |
| `wordRange` | | `[下限, 上限]`，两个数字 |
| `minGrade` / `maxGrade` | | 1-9 的**整数**（不是字符串），`minGrade ≤ maxGrade` |
| `focus` | | 只能从 `observation` / `structure` / `vocabulary` / `imagination` / `emotion` 里选 |
| `tagId` | | 细分标签，可以留空。**写中文也认**（「天气」和 `weather` 等价，入库时自动归一） |
| `images` | | 见上 |

`lead` 是这道题的灵魂，值得多花时间：**不要写成作文要求，要写成一句问话**。
「下雨之后，校园里有什么不一样了？」比「请描写雨后校园的景色」好得多。

## 六、排错

| 现象 | 大概是 |
| --- | --- |
| 闸门说 `category「写景文」不认识` | 只能写那 5 个英文键或 5 个中文名，没有「写景文」 |
| 闸门说 `图片不在 public/ 下` | 图片没复制进 `public/photos/`，或者路径多写了/少写了斜杠 |
| 闸门说 `sceneKey ... 不存在` | 拼错了。去 `src/assets/scenes.tsx` 的 `SCENES` 里找真的 key |
| 闸门说 `focus 里有不认识的值` | 只能从那 5 个维度里选 |
| 导进去但列表里看不到 | 检查筛选条件（年级 / 类别 / 只看收藏）是不是卡住了 |
| 有配图但显示的是别的场景 | 那条的 `images` 是空的，缩略图用了默认场景 |
| 图一直是占位画 | `imageUrl` 挂了，而这条又没有 `sceneKey` 兜底 |
| `--recent` 列出来的图不是我贴的 | 挑错了。对着时间挑，或者直接用图片路径 |
| 脚本说 `找不到 Chrome` | 缩放跑不了，图会按原尺寸拷。设个 `CHROME_PATH` 再试 |
| 脚本说「缩放反而更大，留原图」 | 正常 —— PNG 重编码有时会涨，脚本宁可留原图也不撑大包 |
| 转成 `.jpg` 之后图变糊了 | 截图/带文字的原图加 `--no-convert`，只做同格式缩放 |

## 七、别忘了：改了图要重新构建

`public/photos/` 里的图片是在**构建时**打进 `dist/` 和 APK 的。
在浏览器里 `npm run dev` 是即时生效的，但：

- 要出 APK：`npm run apk`
- 要出网页版：`npm run build`

**已经在手机里装好的 App 不会自己更新** —— 新图片要重新打包安装才看得到。
（这也是推荐 https 外链的原因：换图不用重装。）
