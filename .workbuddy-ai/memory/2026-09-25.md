## 19. 「旅游点名录浏览」点卡片就能编辑（家长提的）

家长看完 ③ 的编辑器之后问：

> 「为啥不是 直接 用 旅游图 landmarks-browse.html，点击选项就出现 编辑。」

**他说得对。** 我当初分成两个页面，只有两条理由站得住：

1. 编的是两份不同的东西 —— browse 读**地标数据**（4 个文件、1808 条，只读，是"来源给的"）；
   编辑器读写**内容包**（`travel-contents.json`，是"我们给的"）。
2. 规模差三个数量级 —— browse 是**审阅**界面（省/市/等级/知名度），编辑器是**写作**界面。

⚠️ **第三条理由不成立，我当时是这么想的**：「一个是静态页、一个要 dev server」——
browse 页里那行 `await import('./src/data/landmarkFame.ts')` 也是 TS 模块，
**它本来就必须走 dev server**。

★ 而且缺一环：**browse 页压根不读内容包** → 1808 个景点里哪些写过了，在这一页上一点看不出来。

### 19.1 家长的两个选择

- 整合方式 → **「抽屉里嵌编辑器」**（不搬那 900 行，用 iframe 内嵌）
- 要不要顺便让 browse 页认识内容包 → **「要：卡片上加标记 + 筛选」**

### 19.2 做了什么

**`landmarks-browse.html`**
- `loadContent()` 读 `travel-contents.json`，按 `landmarkId` 索引成 `CONTENT`
  （⚠️ 只收**有 landmarkId** 的；野点不属于任何地标）
- 卡片右上角：配过的挂 `内容 N` + 等级色点（颜色从 `TRAVEL_GRADES` 读，
  **不在这一页再抄一份五档**）；**没配的不显示任何东西**（1801 条都是空的，
  全挂「未配」会把真信息淹掉）
- 筛选栏加 `#fContent`：全部 / 只看还没配内容的 / 只看已配内容的
- 统计条加「已配内容的景点 `5 / 1808`」（按**地标**数，不是内容条数）
  —— 抽成 `renderStats()`，因为存完要重画
- **整张卡片可点**（事件委托挂在 `#result` 上，不给每张卡挂 onclick）
- 右侧抽屉 + 灰底遮罩，里面是 `<iframe src="./travel-editor.html?embed=1&id=xxx">`

**`travel-editor.html`**
- 认 `?embed=1`（藏掉左边那份地标列表、藏掉顶栏 h1/hint、高度改 auto）
  和 `&id=xxx`（定位到那个景点；**没有内容就当场起一条空白的**）
- 所有改 `dirty` 的地方收成一个 `setDirty()`，它顺手 `postMessage` 给父页
- `beforeunload` 在 `embed` 下**故意不挂**（见 19.3）

**两个页面的连接点**（双向 postMessage）：
| 方向 | 消息 | 干什么 |
| --- | --- | --- |
| 编辑器 → browse | `lwm-dirty` | 抽屉显示「● 有未保存的改动」、关闭前要问 |
| 编辑器 → browse | `lwm-saved` | 父页重读内容包 → 标记/统计/筛选**当场**刷新 |
| browse → 编辑器 | 无 | 一切通过 URL 参数（`embed` / `id`）传 |

### 19.3 ★★ 三个只有真浏览器才暴露的坑

1. **★★ 一次「关闭」会连弹两个确认。**
   父页的 `confirm` 之后，父页把 `iframe.src` 改成 `about:blank` →
   **iframe 自己的 `beforeunload` 又弹一次**（点「关闭」本身就是用户手势，
   所以浏览器肯弹）。家长会看到两遍「要丢掉改动吗」。
   ➜ 编辑器在 `embed` 下**关掉自己的 beforeunload**，只留抽屉那一条。
   ⚠️ **反过来说：父页必须自己挂一个** —— 否则关标签页照样静默丢散文。
   ★ 教训：**同一件事的守卫只能有一处**，内嵌组件尤其容易两边都挂。
2. **★★ 自动生成的空白条目不算「改动」。**
   点一个还没配内容的景点时，`addFor()` 会当场造一条（标题/地名/坐标都填好）。
   它会 `setDirty(true)` —— 于是家长**点开看一眼就关掉**也会被问
   「有未保存的改动，确定关掉？」。
   ➜ 造完立刻 `setDirty(false)`。
   ★ 假警告比没有警告更坏：**它会训练用户闭着眼睛点"确定"**，真有改动时也照点。
3. **★ 关抽屉必须把 iframe 卸掉**（`src = 'about:blank'`）——
   不卸的话下次点开还是上一份没保存的状态，看起来像"这个景点现在的内容"。

### 19.4 ★★ 写 e2e 时踩的两个坑

1. **⚠️ 一次操作弹两个 dialog，只记最后一条 = 误判。**
   第一版只留 `lastDialog`，断言「弹了确认」时拿到的是后面那个
   **空的 beforeunload**，于是报红 —— 而我差点去"修"一个根本没坏的 `closeDrawer`。
   ➜ 改成把**所有** dialog 都 push 进数组，再分别断言
     「confirm 恰好 1 条」+「beforeunload 恰好 0 条」（后者才是双弹的守卫）。
2. **⚠️ `page.on('dialog')` 只能注册一个。** 注册第二个 → 两个都去 accept →
   `Cannot accept dialog which is already handled!`，脚本直接崩。
   ➜ 一个处理器同时记文案 + accept。

## 20. ★★ 抽屉里的「这一组的图」条带（家长提的）

家长的需求原话：

> 「每个旅游点 会有多张图，每个图 都有 item，对应等级，散文等。
> 之后 小鸟到这个点 会根据时间随机的选取一张，给不同的用户，不同时间 差异性。
> 你安排下 抽屉里 图片 新建的 UI 设计 和展示。」

### 20.1 先说清「已经有的」和「真的缺的」

- **数据模型早就支持一个地标 N 条内容**（`landmarkId` + `grade` + `essay` 都在），不用改。
- **「小鸟随机选一张」也已经实现了** —— `dispatchBird` 走 `pickContent()`，**等概率**。
  所以家长只要给一个景点加上第 2、3 张，孩子下次来**就会看到不一样的那张**。
  ⚠️ 但 `grade` **故意不参与**（`TRAVEL_GRADES` 没有 `weight` 字段）—— 等级只做标注。
- **真正缺的是"看得见"**：抽屉里左边那份列表被藏掉了 →
  这个景点一共几张、我在改哪一张、怎么再加一张，**一个都看不见**。

### 20.2 做了什么

`travel-editor.html` 加一条**只在 embed 下出现**的条带（`.strip`）：

```
这个景点的图 · 2 张
[长城之秋 (照片)   ] [长城上的笑声      ] [＋ 新建一张      ]
[■ 绝景 · 有散文   ] [ 笑话 顺路·还没散文] [给这个景点加图    ]
  ↑ 选中=黑描边        ↑ 等级色条(底边)     ↑ 虚线框
```

- `renderStrip()` **只列 `landmarkId === FOCUS_ID` 的那几张**（不复用全库的 `renderList()`）
- 每张给三个信息：缩略图 / **等级色条** / **有没有散文**（橙色标出"还没散文"）
- `addFor()` 改成**只有第 1 张预填标题**（第 2 张起留空，逼你各自起名）
- 点「＋ 新建一张」→ 加一条 + **光标直接落到「媒体地址」**（加完第一件事就是贴图）
- 点任一张 → 切换表单在编哪条（改动都还在内存里，不会丢）

**顺手修的一处（同屏两个数字打架）**：
抽屉标题写着「已有 2 条内容」，点一下「＋ 新建一张」条带变 3 张 → 标题还写 2。
➜ 编辑器把**这一组的条数**一起报回来：`postToParent({type:'lwm-dirty', dirty, count})`；
宿主刷新并补一句「（还没存）」。顺手把重复拼了两遍的那句文案收成 `renderDrawerSub()`。

### 20.3 ★★ 找到的真 bug：行内元素吃掉 `height`

`.th` 是 `<span>`，CSS 给了 `height:74px` —— **`<span>` 默认 inline，height 直接被忽略**，
不报错、不警告。于是缩略图高度由内容决定：

- 照片方块跟原图比例 → **110px**
- 文字方块跟那行字 → **60px**
- 「＋ 新建一张」→ 74px（它的规则里另有 `display:flex`，歪打正着）

量出来：`.th` 高度集合 = `[110, 60, 74]`；加 `display:block` 后 = `[74]`。

⚠️ 危害不止"看着歪"：**条带总高随"这组里有没有照片"变** → 抽屉打开时内容往下跳。
⭐ 守卫：**所有 `.th` 的高度集合必须只有 1 个值**（比断言等于 74 更耐改）。

## 22. 三处界面修正：信息条挪到顶 / 「这张图」分组 / 那条绿线（09-25 下午）

家长原话：

> 「这个景点（只读 —— 这些字段属于地标，不随这一张图走）… **这个 放到顶上去**。
> **图片item 归图片。** 还有界面好像**中间多了一条 绿线**。」

三件事**都在 `travel-editor.html` 一个文件里**，一次改完、一次验收。

### 22.1 绿线：根因是「定位祖先落空」

★★ 不是"多画了一条线"，是**色条画错了地方**。
`.tile .gbar{position:absolute; bottom:0}`，但 `.tile` 是 `<button>`、
**`position:static`** —— `bottom:0` 要找"最近的定位祖先"落空，
一路升到**初始包含块**，在抽屉里画成一条**横贯整个 iframe** 的条。
探针实测：

```
gbarRect   [0, 835, 879, 4]        ← 879 = iframe 宽，不是 104（缩略图宽）
offsetParent  body.embed            ← 本该是 .th
chain  span.gbar(pos=absolute) → button.tile(pos=static) → div#strip → div.wrap → body
```

修法：把 `<span class="gbar">` **拼进 `.th` 里面**（`.th` 本来就是 `position:relative`），
两个分支（有图 / 占位）都带上。修完实测 `w:102 / thW:104 / parent:"th"`。

⚠️ **顺手可得的两个好处**：`.th` 是 `overflow:hidden` + `border-radius:10px`
→ 色条下两个角被裁圆，正好贴着方块；占位块（`th bad`）也显示等级色
→ 新加的那张不再是"看不出等级"。

### 22.2 ⚠️ 被否掉的"顺手修法"：给 `.tile` 加 `position:relative`

看着最省事，**量过不能用**：`.t2`（副标题）底边到 `.tile` 底边只剩 **2px**，
4px 的色条会**压穿那行字**（「顺路 · 还没散文」）。

### 23.1 为什么 §22 那次的"放到顶上去"不算做到

§22 我把它挪到了**表单 `.grid` 的第一格**。但抽屉里的实际顺序是：

★★ **判据**：家长说"往上放"，我问的应该是**"上一个它能在的容器是什么"**，而不是"它现在的容器里的第一个位置"。

### 23.2 做法：加一个持久宿主 `#lmslot`，放在 `#strip` 之前
