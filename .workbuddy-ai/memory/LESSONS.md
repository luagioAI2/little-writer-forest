# 小笔苗（little-writer-forest）· 项目长期约定

> 只放**跨会话仍然成立**的规则。日常流水记在 `YYYY-MM-DD.md`。

## 一、AI 边界（最硬的一条，2026-09-19 定）

家长原话：「不许 AI 帮改写。**是 不许 AI 帮写。不是 不允许改写。** 把正在去掉可以，
小明后面加小红可以，把小明改成大明可以。但不允许 AI 自己生产内容 —— 类似『给这个句子加点比喻』都不行。」

**判据是「内容从哪来」，不是「谁在操作」**：那些字是**孩子自己说的** → 可换/删/挪/插；
内容是 **AI 造的** → 不许润色/扩写/加比喻/想结尾。「AI 一个字都不许参与」是**读窄了**，AI 可以来"听懂"。

- ★ **不靠提示词求它别写，靠接口形状让它写不了**：模型返回 `ParsedEditInstruction`，
  类型里**没有"正文"字段**（权威注释在 `src/domain/ai.ts` 四·五节）。
- 链路：孩子口语 → 模型只翻成指令 → **本地 `applyEdit` 执行**。正文只可能出自本地引擎。
- 「要 AI 代写」必须走 `refuse`，**不能混进 `unknown`** —— 回"没太听懂"孩子会一直换说法。
- ⚠️ AI 介入的编辑记录必须标 `by: 'ai'`；鼓励语 / 修改记录标题 / 回执都不许说成「你自己改的」。
- ★★ 2026-09-21 家长定：「改作文 **必须是 AI 模型 处理**。」→ 删掉全部静默退回本地的分支（见 §十三）。

## 二、其他底线

- 改作文找不到目标 / 出现多次时：**停下问孩子，不擅自改**。这是好设计，别优化掉。
- 「小笔苗」这个名字**早就散在 ~25 处文案里**（`db.ts` 默认孩子名、`cards.ts`、`scoring.ts`、
  `LevelPage`…）。吉祥物是给一个**已存在的角色**补身体，不是新增角色。

## 三、★ AI 产出的东西不许用本地模板冒充（2026-09-19）

家长原话：「评价里的东西 都需要 AI 分析。」

- 模型少给字段 → **补问一次**（把它的原话 +「你漏了 X」发回去），不许拿本地模板顶上。
- 补问还不行 → **那一份对象整份退回本地**，并如实标 `engine: 'local'`。
  ⚠️ 评价（`WorkScore`）和写法（`ModelEssay`）是**两个对象**，各自独立定引擎 ——
  绝不许出现「模型给的分 + 本地总评」这种自相矛盾。
- **界面上的 `engine` 必须说真话**：降级了要让家长看得出来，否则「配置没生效」会被伪装成「功能没实现」。
- **骨架类派生数据要从自己那份正文推**（`skeletonFromLines` 串过台）。
- ⚠️ `scoreWork`（只评分那条）**App 里没人调**，仍是旧的静默降级写法；接回界面时先照 `scoreAndRewrite` 改。

## 四、★ 「更好的写法」必须结合图和孩子写的（2026-09-19，第二次报）

家长原话：「要结合 图 和 用户写的」（09-18 已按同一句话改过 → 真因**不在素材层**）。

- 收到「要结合 A 和 B」先问：**输出里有没有跟 A、B 都无关的整句？** 有 → 问题在**生成层**。
- 真因：**分类标签被当成了生成模板的依据**。题库把「看图作文」归在 `category: 'event'`
  （`prompts.ts` 的 `TOPIC_TAGS`）→ 整篇按写事模板编出「手心里全是汗 / 心跳得厉害」——
  跟图无关、跟孩子写的也无关。**它要写的是画面。**
- 规则：**模板的选用依据是「内容里有什么」，不是「它归到哪一类」**。`resolveKind` 要求写事模板必须有"事"。
- ★ **同一个判定只许有一个函数**。「这是什么文体」被两条路需要（本地选模板 / 提示词写「类型：」）——
  提示词那边用 `kindLabelFor`，内部调的是同一个 `resolveKind`。改一条忘一条 = 没改。
- **人工挑过的词表不许再过启发式过滤**：`NOT_A_THING` 是子串判断，把「**雪人**」当成"人称"整条丢掉了。
  启发式过滤只能用在**正则兜底**那一层。
- **正则捕获必须有「像不像名词」的守卫**，否则量词兜底会抽出「开满粉 / 小鸟飞 / 整整齐」。
  取舍：宁可少抽一个生僻名物，也不许把碎词写进孩子看到的内容；**被误伤的出路是加词表**（「飞机」就这么补的）。
- **图可以补孩子没写的地点/时间，但只补空、不覆盖**（孩子写了就一定用他的）。
- AI 那条路配了**跑偏守卫**：一份「必须留住」清单既写进提示词点名要求、又回来后照单核对；
  一条都没留住 = 跑偏 → 带原话补问一次 → 还跑偏就**写法退回本地**（评价不牵连）。
- ⚠️ 已知未修：内置题库「看图作文」只有 2 道，其配图注释描述的是**作业纸排版**，不是画面内容。

## 五、★ 家长设置里的提示词，两条路都要读（2026-09-19，第三次报）

家长原话：「更好的写法，还要结合下 **家长设置里的 提示词**。类似于点比喻之类的。」

- 真因：`extraPrompt` 全项目只有两个消费者，都是 AI 提示词拼装函数；**本地引擎一个字都没读**。
  而设置页写着「AI 点评和改范文时会参考这些要求」→ AI 一降级，这条要求被**静默丢弃**，
  家长只会觉得"设置了没用"。
- ★ **一个设置项只要有多条执行路径，就必须每一条都读。**（本项目反复犯：另见 §四 `resolveKind`/`kindLabelFor`）
- **能做的做，做不到的说**：比喻/拟人/通感/叠词 → `demandSentences` 主动补进正文；
  排比/对话/成语/首尾呼应/细节描写 → `unfulfilledDemands` 认出来，在降级警告里如实点名（`withUnfulfilledNote`）。
  **装作做到了比做不到更坏** —— 家长会一直以为设置生效了，只是孩子写得不够好。
- ⚠️⚠️ **两个上限只补一个 = 没补**（代码写完、类型也过，要求**仍然落不了地**，靠实测才找出）：
  · 修辞判定做在**裁剪之前**的全量候选上 → 判成"已经有了"，可那句随后被裁掉 → 既没补、正文里也没有；
  · 句数上限 `keepCap` 确实加了名额，但**画面句不受它约束地排在最前**，家长那句永远进不去。
  ➜ **判定必须基于裁剪之后的正文；家长点名的句子不参与裁剪。**
- **亮点不许宣称正文里没有的修辞**：`usedRhetoric` 和生成句子的函数读**同一份模块级词库**。
  以前亮点无条件写「加了比喻和拟人」，而写景/写事分支根本没有比喻 —— 家长想知道的正是「有没有落实」。
- 优先级（`base` 的排序就是它）：① 写人时第一句必须是这个人 ② 画面句（"不跑偏"硬标准）
  ③ **家长点名的修辞** ④ 通用套话。家长要求**高于通用套话、低于画面句**。
- ⚠️ AI 那条路**没有做**要求校验：我们的修辞指纹只认自己模板库里的句子（它写「像一根小鞭子」认不出），
  硬校验会**误报**。只把要求写进提示词。

## 六、★ 改作文「理解不行」（2026-09-20，第四次报）

家长原话：「我写了 半大的小学生在操场上玩篮球。我说把 操场后 加上快乐的 玩篮球。他搞了半天。
另外 我说 把玩篮球后面的句号 改成叹号。始终不行。理解不行。」→ 两条都是**真的缺功能**。教训比修法更重要：

- ★★ **孩子最自然的说法（带「把」）100% 失败**：`INSERT_PATTERNS` 里「X 后加上 Y」前缀只写了 `(?:在)?`，
  **漏了「把」** → anchor 被吞成「把操场」→「文中没有找到『把操场』」。
  ➜ **正则的前缀/后缀枚举，每漏一个变体就是一个 100% 失败的口子。** 改这类 bug 先问"孩子还有哪种说法"，逐个试。
- ★ **插入点是"词"的边界，不是"匹配到的那几个字"的边界**：anchor 匹配到「操场」，孩子心里的词是「操场上」
  → `LOCATIVE_SUFFIX = [上中里下内外边面间旁]` 往后贴一格。
  ⚠️ 「前/后」**不收** —— 它们既当方位后缀（门前）又当连接词（然后），会误伤「小明后来走了」。
- ★ **孩子会把"落脚点"念进来说，而落脚点本来就在正文里**：「操场后加上快乐的，玩篮球那儿」照字面插
  → 「快乐的玩篮球玩篮球」。守卫：插入内容与**紧接着的正文**尾部重合 **≥2 字** → 削掉（削掉的本就在，不丢字）。
  ⚠️ **必须 ≥2 字**：只重合 1 字是巧合 —— 「加上快乐的」而正文紧接着「的玩篮球」时会把「的」削掉得到「快乐玩篮球」。
- ★ **标点是一整类缺失，而且是两层根因**：① 孩子说**名字**（句号/叹号），正文里是**符号**（。/！）；
  ② 「X 后面的那个标点」是**相对指位**，旧代码只有字面量查找。
  ➜ 新增 `kind: 'replace-punct'`，`from`/`to` 存**真符号**（名字→符号在解析那步翻完）；
  `EditOperation` 里也存符号，否则 diff/撤销对不上正文。
- ★ **`PUNCT_PATTERNS` 必须排在通用替换之前**（否则整串被通用替换抓走再报"找不到"；变异 M6：12 条红）；
  「最后/第一个」两条**必须排在"参照物"那条之前**（否则 `(.+?)` 把「最」当参照物、「后」当方位词，M5）。
- ★ **有多个候选时停下来问，但孩子自己指好了就别问**：「把句号改成叹号」+ 多个句号 → 弹候选（`ambiguous`）；
  「把**最后的**句号改成叹号」是他指定了，直接改（`pick: 'last'`）。
- ⚠️ **`replace` 和 `replace-punct` 的消歧分支要共用一份判定**（`replacePairOf`）。
  两处各写一次 → 加了标点那支就会漏，表现是"出现多次时面板弹不出来"，**不报错、只是没反应**。
- ⚠️ 已知未做：统称「标点」「符号」（不指定是哪一个）不支持 —— 要支持得让 `from` 变成字符类，
  `replaceAt` 的跨度就得按**实际匹配到的长度**算（省略号是 2 个字符），容易埋跨度 bug，先不做。

## 七、★ 一个设置项/一个默认值改了，老存档不跟着走（2026-09-20）

- 改 `defaultAiConfig()` **只对"新装"生效**：存过设置的用户那边 `{ ...defaultAiConfig(), ...s.ai }`
  里 `s.ai.model` 会把默认值盖掉 → 家长只会得出「你改了但我这边一点变化都没有」（同 §五）。
  ➜ 换默认模型时**同时**加迁移：`migrateRetiredDeepSeekModel` 只把「我们预置过的旧名 + 官方 base_url」
  换成正式名，家长自己填的模型一律不碰。
- ★ **同一个字符串在三处各写一遍 = 迟早漂移**（`deepseek-chat` 曾同时在默认配置、服务商预设、设置页 placeholder）。
  现在只有 `DEFAULT_DEEPSEEK_MODEL` 一份。
- 收尾要 grep **打包产物**：新名应在，旧名只应出现在 `RETIRED_DEEPSEEK_MODELS` 里（那是迁移要认的旧名，**故意留的**）。
- ⚠️ **模型名权威结论（2026-09-21 查证）**：DeepSeek V4.1 Flash 的正式调用名是 **`deepseek-flash`**
  （七牛云「官方 API 模型名为 deepseek-flash」+ 新浪「将模型名称更改为 deepseek-flash 即可调用」）；
  `deepseek-v4.1-flash` 是**阿里百炼**的名字，不是 DeepSeek 的；beta 名 `deepseek-v4.1-flash-expires-on-0910` 已退役。

### 7.1 ★★ 同一个病换个字段又来一次：`transcribe.engine`（2026-09-21）

家长报 **「写作文 录音 好像有问题了。之前正常的。」** ——「之前正常的」= 这是回归。

- `transcribe.engine` 也是**后加**的字段；而 `defaultTranscribeConfig()` 后来从
  「整包上传（硅基流动）」**换成了**「火山流式」。老存档没有 `engine`，于是
  `{ ...defaultTranscribeConfig(), ...s.transcribe }` 拼出**自相矛盾**的一份：
  `engine:'volcengine'`（新默认值）＋ 硅基流动的 `sk-` 密钥 / baseUrl / model（老存档）。
- **为什么它一声不响地坏**：两个判定各自看一个字段，**都说"能用"** ——
  `usesStreamingEngine()` 看 `engine`（真）、`isTranscribeConfigured()` 看 `apiKey` 非空（真）。
  于是界面切成「按住说话」，然后**拿 A 家的密钥去连 B 家的服务** → 握手被拒 → 一个字都没有。
  没有异常、没有日志、没有提示，家长只看到"录音不好使了"。
- ★★ **判据升级（这条比修 bug 本身值钱）**：
  给持久化配置**加字段**时，必须问一句
  **「老存档缺这个字段时，拼出来的配置自不自洽？」**
  · 自洽 → 直接 `{ ...default, ...saved }` 就行；
  · **不自洽 → 必须写迁移**，而且迁移的判据是**"让各个字段互相自洽"**，
    不是"把新默认值塞进去"。
  本次实现：`migrateTranscribeConfig`（`src/db/db.ts`）。自洽的定义很具体 ——
  **火山 ⇒ `baseUrl` 必须空**；**整包上传 ⇒ `baseUrl` 必须非空**。
  于是"老存档没有 engine 但有 baseUrl" ⇒ 它一定是整包上传那套。
- ⚠️ **同一族的第二个面：两条路**共用字段名**。**
  两家的密钥都叫 `apiKey`，而设置页那个「火山」按钮原本写的是
  `apiKey: tr.apiKey.trim() || VOLC_TEST_API_KEY`（"别覆盖家长填的"）——
  好意，但**从硅基流动切到火山时会把 `sk-` 密钥带过去**，又造一份自相矛盾。
  ➜ **切路由时必须换掉属于另一条路的凭据**；只在"已经在这条路上"时才保留。
- **验证方式**（可复用）：写个临时探针，把**存档形态**当参数横扫
  （老存档 / 已写坏 / 纯火山 / 家长自填 / 全新用户），断言
  **"合并后一定自洽"**，而不是只测一个 case。再用真实服务跑一次端到端。
  变异验证：还原成出 bug 的那一行 → **恰好 4 条新守卫变红**、两条"不许动"的仍绿。

## 八、★ 新手引导（2026-09-20）

- **`onboarded` 和 `guideDone` 是两个开关，不许合并。** 前者 = 要不要**问**（昵称/年级/目标），
  后者 = 要不要**教**（怎么用）。合并的后果：「再看一遍引导」会把一年才改一次的东西再问一遍。
- ★ **引导的第一目标不是"介绍功能"，是"让他把手势做一遍"。** 核心手势只有「按住说话」，
  而孩子会去**点**那个麦克风（配好转写时点一下确实没反应）→ 他以为坏了。
- ★★ **但"按住"不是唯一的手势 —— 引导教哪个必须跟着设备走。** 转写没配好 / 在网页上跑时，
  按钮是「点一下开始、再点一下停」。➜ 抽出 **`canHoldToTalk(cfg)`（`platform/transcribe.ts`）**，
  `VoiceComposer` 和引导**共用这一份判定**（`App.tsx` 传 `canHold` 给 `Guide`）。
  两处各判一次就会漂移 —— 引导教按住、按钮却是点击，孩子按住不动、界面毫无反应，
  **而那正是这个引导存在的理由，被它自己搞砸最讽刺**（同 §六 的 `replacePairOf`）。
- ★ **引导里绝不申请麦克风权限。** 演示是**纯脚本**（不碰 `getUserMedia`）：孩子还不知道这 App 干嘛
  就弹权限框，拒绝一次就再也不给了；而 WebView 里没权限时录音会**静默失败**。
- **状态槽高度写死 `h-12`**（同 §十二 那个坑）。
- **引导里说的东西必须都是真的**：
  · 第一屏三格成长树用的是**真实** `MiniTree`，最后一格必须是**真正的最后一段**（第 12 段通天神树）——
    箭头是递进的，最后一格会被读成"长到头的样子"（最初写成第 10 段星辰树，**截图走查**才发现）。
  · 树洞有段位门槛（第 4 段才开），引导里必须说出来，否则孩子当天就去日记本扑空。

## 九、工程习惯

- ★★ **协作方式（2026-09-20 家长定，最高优先）**：
  「stop doing unrequested work. Confirm with me before proceeding.
   do not deploy or commit anything without my explicit permission.」
  · **不做没被要求的事** —— 最容易越界的是"顺手多扫一圈"：家长报 A，我扫出 B、C 就顺手修了。
    **额外发现的 bug 不是功劳**，它扩大改动面、把复验成本转嫁给家长。➜ **发现了先报告、等确认，再动手。**
  · 动手前先确认（尤其"改哪些文件 / 改多大范围"）。
  · **不许 build / 打 APK / 部署 / 提交**，除非明确说可以。（本目录不是 git 仓库。）
- 注释写**为什么**，尤其是"曾经踩过的坑"。本仓库大量注释是刻意的，别精简掉。
- 需求变更要留痕：在改动处的注释里写清"原来是什么 / 为什么改 / 原话引用"。
- 颜色改动：**hex 和 `rgb()` 两种写法都要扫**（`shadow-[...rgb(47_122_92/0.6)]` 这类 Tailwind
  任意值里没有 hex，只扫 hex 会漏 —— 已漏过 6 处）。
- **SVG 的 viewBox / 尺寸不许写死成一个数字**，要由布局常量推出来。写死过 `0 0 360 H` →
  图偏右（左空 62 / 右空 8）且**不报任何错**。同一份尺寸也别声明两遍。
- 验收要走到**打包产物**：`grep` dist 里"旧串应为 0 / 新串应 > 0"。打 APK 时另有 `scripts/_verify-apk.mjs`
  做包内校验 —— ★ **每加一个功能就要往它的 `FEATURES` 里补一条特征串**，否则它只验证上一轮的东西，
  "校验通过"变成一句空话。判据用 **bundle 文件名 / sha256**，不要用体积。

### 14.1 为什么 §一 的"接口形状"还不够

§一 的第一道防线是 `ParsedEditInstruction` 里**没有"正文"字段**。它挡住的是**量** ——
模型不能整篇交稿。但**拦不住它在 `to` / `text` 这些自由字符串里塞自创的字**：
`{ kind:'insert', anchor:'操场', text:'快乐的' }` 与 `text:'欢快活泼的'` 在类型上完全一样。
所以需要**第二道防线**：不问"你想写多少"，问**"这几个字你从哪来的"**。

### 14.2 ★★ 来源铁律（`src/domain/provenance.ts` 的 `checkProvenance`）

> 改完之后，正文里的每一个字必须来自 **①原文** 或 **②孩子那句话**。没有第三个来源。

- **写入侧**（`to` / `text`）：必须是**孩子那句话的子串**。
  ⚠️ **子串 = 连续匹配**，不是"这些字都在那句话里出现过"（`狗小` 与 `小狗` 用字相同，含义相反）。
- ⚠️⚠️ **必须开的那一个口子：标点「名字→符号」白名单。**
  孩子说「把玩篮球后面的**句号**改成**叹号**」，而指令里 `to` 带的是「**！**」——
  它**不是**「把句号改成叹号」的子串。照字面卡，**改标点这一整类 100% 被误杀**，
  而那正是家长 09-20 报的「始终不行」。所以 `PUNCT_NAME_TO_SYMBOL` 把
  「句号→。」「叹号/感叹号→！」「省略号→……」等映射进来。
  ★ **放行是有条件的**：只有他**点过名的**标点才算"他说过的"——
  他说叹号，模型就塞不进问号（`allowedPunctFrom(utterance)` 现算，不是一张固定的放行表）。
  ⚠️ **多字符标点（`……` / `——`）要整体先摘再逐字过滤**，否则 `……` 会被拆成两个 `…`，
  而 `…` 不在白名单里 → 仍然误杀。
- **定位侧**（`from` / `target` / `anchor` / `near`）：**闸门不在这里查原文**。
  那是 `applyEdit` 的活，它报得更准（能区分「文中没有找到」和「出现了 3 次，你想改哪一个」）；
  闸门再查一遍只会产出一句更差的提示。对定位侧**只卡长度**。
- **跨度上限 `MAX_SPAN_CHARS = 40`**：防"把整段重写"伪装成"替换"（`from` 是整段、`to` 是它重写的）。
  写入侧和定位侧都卡。
- 越界 → `reason: 'invented'`，文案「这几个字你没说过 —— 要加什么，你直接说出来，我就给你加上」。

### 14.3 ★ 指位：`near` / `side` / `pick`（同一天补完，治 §十一 那个结构性根因）

孩子常常**不说那个字，只说它在哪儿**：「把玩篮球**后面的那个字**去掉」。

- ★★ **根因**：`ParsedEditInstruction` 里**只有 `replace-punct` 带 `near`**，
  `delete` 是 `{target}`、`replace` 是 `{from,to}`、`insert` 是 `{anchor,position}` ——
  模型**根本没有字段**可以表达"是哪一处"。这不是提示词写得不清楚，是**类型里缺东西**。
  ➜ 抽出 `OccurrenceHint { near?, side?, pick? }`，**推广到 `replace` / `delete` / `replace-punct`** 三种。
- ★ **`OccurrenceHint` 只声明一次**（`voiceEdit.ts`），`ai.ts` 用 `import type` 引进来 ——
  声明两遍就会漂移（同 §四「同一个判定只许有一个函数」）。
- ★ **定位只有一份判定，措辞各写**：`locateOccurrence(text, needle, hint)` 返回
  `hit` / `not-found`（带 `why: 'anchor'|'beside'|'target'`）/ `ambiguous`；
  `replace` / `delete` / `replace-punct` 三个分支**各自渲染自己的话**
  （「「操场」出现了 2 次，你想改哪一个？」/「要删哪一个？」/「文中有 2 个句号，你想换哪一个？」）。
  ⚠️ **措辞塞进共用函数会让三支互相打架**；判定留一份、话各说各的。
- ★ **`near` 只在两种情况才需要**：① 目标在原文里**出现多次** ② 孩子**没说那个字**、只说了它相对谁。
  其余**不要加**，让程序自己找唯一的那个。提示词里写明了这条，否则模型会到处乱加 `near`。
- ★ **提示词要告诉模型"你看得见原文"**：让它先自己往下读一眼，把"他指的那一处"落成
  **原文里真实存在的字**再填进 `from` / `target`。
  例：「把玩篮球后面的那个字去掉」+ 原文「…在操场上玩篮球。」→ `{ kind:'delete', target:'。', near:'玩篮球' }`。
- ★ **孩子自己指好了就别问**（`pick:'first'|'last'` 直接改）；没指且不唯一才 `ambiguous` 弹候选（同 §六）。

### 14.4 记录面板：原文那句 / 改成 / 你说

- 「原文」「改成」用 **`sentenceChange(before, after)`** 扩成**整句** ——
  光给「小猫 → 小狗」，孩子不知道是在说哪一句。
- ⚠️ **往后找句末要从 `to - 1` 起步，不是 `to`**：变化区自己常常就以句末标点收尾（删掉一整句时），
  从 `to` 起步会越过它继续吃下一句，把**没被改的那一句**摆进「原文」栏。
- ⚠️ **追加（append）时 before 侧的变化区是空的**（公共前缀把整段吃光）→
  要退回"**紧邻**变化点的那个字"所在的句子，否则「原文」那栏是空白，看起来像记录坏了。
- 「你说」= `EditOperation.said`，**逐字原话**（只有 `by:'ai'` 才填得出来；孩子自己动手改的没有"输入的话"）。
- ★ `changedSpan` 与 `sentenceChange` **共用 `diffBounds`** —— "哪儿变了"只许有一个判定（同 §四）。
  `changedSpan` 自身仍是**被禁的**（当年用来从两篇**独立全文**猜改动，那是猜）；
  `sentenceChange` 安全的前提是**这两份 before/after 是同一次定点拼接的两端** ——
  这是**结构性保证**，不是猜。注释里写清了这条区别，别把 `changedSpan` 一起复活。
- ⚠️ 改这个面板会撞坏两条老用例：它们用**"界面上搜不到这句指令"**当"没被追加进正文"的替身，
  而「你说」一栏现在**故意**显示孩子原话 → 替身失效、变红，看着像新功能弄坏了老功能。
  **改成直接断言 `holder.text`**。
  ★ 教训：**替身断言会腐烂** —— 一旦那个字串开始被合法渲染，"搜不到"就不再是证据。

光看界面**永远发现不了** —— 家长只会说"名字没了"，而你在设置页怎么看都看不出问题。

➜ 这类 bug 的出路是**单元测试**。而且 jsdom 有个"幸运的缺陷"：
**它点击按钮不会让输入框失焦**，于是真机上"有时行有时不行"的时序问题，
在测试里是**必然复现**的。

三条探针（先打印真实行为，不靠推断）：

| 操作 | `store.childName` | 输入框显示 |
|---|---|---|
| 打完名字**不失焦**直接点头像 | `小笔苗`（没保存！） | `豆豆` ← 看着对，其实没存 |
| 打完名字 → 失焦 → 点头像 | `豆豆` ✓ | `豆豆` |
| 清空输入框 → 失焦 | `''` ← **被写成空串** | 空白 |

### 15.3 修法（家长定的两条）

1. **空昵称 → 回到「小笔苗」**（和引导页「不填也行，那就先叫小笔苗」同一条规则）
2. **边打边存 + 点头像也存**（不再依赖失焦）

```tsx
const commitName = (raw: string) => {
  const next = normalizeName(raw)          // ← 空值兜底在这里，落盘前就换掉
  if (next === settings.childName) return
  void updateSettings({ childName: next })
}
// onChange: setNameDraft(v); commitName(v)        ← 边打边存
// onBlur:   commitName(nameDraft)                 ← 保留，但多数时候是空操作
// 头像 onClick: commitName(nameDraft); updateSettings({ avatar: a })
```

★ 名字最长 12 个字，逐次落盘的开销可以忽略 —— 换来的是"不会白打"。

### 15.4 顺手把默认名收成一份

「小笔苗」原本在**三处**各写一遍：`db.ts` 的 `defaultSettings()`、引导页的兜底、设置页的兜底。
加第三处 = 制造漂移（同 §七 / §四）。

现在只有一份：`src/domain/types.ts` 的 **`DEFAULT_CHILD_NAME`**；
`db.ts` / `Onboarding.tsx`（含 `placeholder` 和提示文案）/ `SettingsPage.tsx` 都引它。

### 15.5 验证

- 新增 `src/features/settings/SettingsPage.test.tsx`，**7 条**（含一条对照组）。
- ★ **变异验证**（临时脚本，验完已删）：
  · M1 还原「边打边存 + 点头像也存」→ **红 5 条**，对照组仍绿
  · M2 还原「空值兜底」→ **红 3 条**
  · 两个变异**各自红在该红的那几条**上 —— 判据真能分辨，不是空断言。

`scripts/_verify-apk.mjs` 的 `FEATURES` 表按**特征串**匹配，

## 十六、★ 一个函数有多个"出口"，就会有人选错（2026-09-22，家长报）

家长原话：「现在的版本 非常好。就是背诵完 点领取奖励。好像回到的页面不对，
还是在当前写的。是不是不合理。」

### 16.1 事故

`ComposePage` 的 `reset(backToSetup = true)` 有两个分支：

| 参数 | 行为 |
|---|---|
| `true`（默认） | 回出题页，清掉当前题目 |
| `false` | **同一个题目 `beginWith(prompt)`** → 新建一篇空白稿、直接进写作页 |

背诵那一步传的是 `reset(false)`：

```
背诵 → 领取奖励 → reset(false) → beginWith(同一个题目) → 新建空稿 → 写作页
```

孩子看到的：一句「背诵奖励 +N 金币」的提示，然后**一篇同名的空白作文**。

### 16.2 ★ 两个佐证 —— 说明这是**误用**，不是设计

1. **`reset(false)` 全项目只用了一次** —— 就是背诵这里。
   其他所有出口（点评页的「回到出题」、离开确认、`handleBack`）都用 `reset()`。
2. **注释里说的那个「再写一篇」按钮根本不存在** —— `grep 再写一篇`
   只命中 `reset` 自己的那段注释。也就是说 `false` 这一支**只为背诵那条路而存在**，
   而它的注释却在为一个不存在的按钮辩护。

★ 这两条一起指向一个通用判据：
**"某个分支只有一处调用、而它的注释在解释一个不存在的东西" = 误用的强信号。**
查这种 bug 最快的办法是 `grep` 那个参数值的**全部**调用点 —— 只有一处就该起疑。

### 16.3 修法：删掉分支，而不是加测试

家长定「回到出题页」。调用点改成 `reset()` 之后，`backToSetup` 参数
**零调用者**了 —— 于是**按家长要求把它和 `false` 那一整支删掉**。

为什么删比留好：
- 留着 = 下次又有人传 `false` 的地雷（这次的 bug 就是这么来的）；
- 删掉 = **全流程的出口只剩一种**，"选错出口"这类 bug **结构上不可能再犯** ——
  这比加一条测试更硬（测试是"看着它别犯"，结构是"它没法犯"）。
- 要恢复"同一题目再写一篇"，得**先有一个真的按钮**，再把分支加回来。

### 16.4 ⚠️ 为什么这次没加自动化测试（说明，不是偷懒）

- 这条 bug 在**接线**上（哪个回调传给了 `ReciteView`），不在某个纯函数里。
- `step` 是 `ComposePage` 的内部 state，**没法从 store 直接播种**，
  要走到背诵步得完整驱动 写 → 点评 → 写法 → 背诵 四步。
- 而写作台的正文**只能靠语音输入**（`VoiceComposer` 里没有正文输入框），
  jsdom 里要额外 mock 识别器 —— 成本高、且脆。
- 所以选了**结构性修复**。⚠️ 但这是个取舍，**不是"这条不需要守"** ——
  哪天有了可播种的步骤状态，就该把它补成测试。

## 十八、★ 把密钥挪出仓库 = 多了一种「静默失败」（2026-09-22）

### 18.1 起因

`src/platform/transcribe.ts` 里明文写着火山 App Key。它会**被打进 APK**，
`strings` 一下就能抠出来，而火山按音频时长计费（¥66/30h）——
密钥公开 = 别人可以拿它刷你的钱。

★ 讽刺的是**那段代码的注释自己早就写了修法**：「要对外发，就挪到构建期注入
（`.env` + `VITE_` 前缀），让仓库里不留明文」。这次只是照做。

### 18.2 做法

| 文件 | 内容 | 入库 |
|---|---|---|
| `.env.local` | `VITE_VOLC_API_KEY=<真密钥>` | ❌ |
| `.env.example` | 空占位 + 说明 | ✅ |
| 源码 | `import.meta.env.VITE_VOLC_API_KEY ?? ''` | ✅ |

### 18.3 ★★ 教训一：挪走密钥，就多了一种**不报错的**失败

「密钥不在仓库里」的代价是：**构建和运行都失去了那个值**。
`.env.local` 没建 → 包里 apiKey 是空串 → 装到手机上「按住说话一个字都出不来」，
而 **构建成功、包内校验全绿**。

**判据（可以推广）**：任何「把常量从源码挪到外部来源」的改动，都要问一句
**「这个来源缺席时，会发生什么？报错，还是静默降级？」**
—— 静默降级的那种，必须补一条校验。

### 18.4 空值语义要跟既有的那一个对齐

`AI_TEST_API_KEY` 早就是空串，语义是「不内置、留空 = 走本地规则，降级不报错」。
新的 `VITE_VOLC_API_KEY` **照抄这个语义**（留空 = 退回系统识别）。
★ 别自作主张改成"启动时报错" —— 那是另一套约定，会把"没配"变成"打不开"。

### 18.5 `.gitignore` 别写成 `.env*`

要忽略 `.env` / `.env.local` / `.env.*.local` 三条**分别写**。
写 `.env*` 会把**要入库的 `.env.example` 一起忽略掉** ——
而那个文件是别人 clone 下来唯一的说明书。
★ 判据：改完立刻 `git check-ignore -v .env.local .env .env.example` 跑一遍，
**要看到 `.env.example` 不在输出里**。

### 18.6 ★ 校验要读**外部来源**，不能把密钥抄进校验脚本

`_verify-apk.mjs` 新加的第 ③ 条：期望值**从 `.env.local` 现读**。
❌ 不能把密钥字面量写进校验脚本 —— 那等于把密钥又搬回仓库，这次重构就白做了。
✅ 读不到就**明确跳过并说清后果**（CI / 别人 clone 下来没有这个文件是正常的），
不能让它在那样的机器上永远红。

**变异验证**（两处都要真跑）：

| 输入 | 构建 | bundle | 含密钥 | ③ |
|---|---|---|---|---|
| 有 `.env.local` | exit 0 | `index-BmwcmIV0.js` | 是 | ✓ |
| 移走 `.env.local` | **exit 0** | `index-C1uQ_aRb.js` | 否 | ✖ |

⚠️ 第二行**构建是成功的** —— 又一个「光看 exit code 不够」的实例（同 §十）。

### 18.7 ★★ 判据：这类重构，最强的验收是「逐字节相同」

密钥从「源码里的字面量」变成「构建期注入的同名值」，**包里的字节应该一模一样**。实测：

- bundle 名 `index-BmwcmIV0.js` 与改前相同
- APK md5 `b5b50071627d4e2dbe49f1684f3a4863` 与改前相同

**逐字节相同 = 零行为变化**，比"我跑了一遍看起来没问题"硬得多。
（能做到，是因为注入的值与原来的字面量相同 —— 这正是想要的。）

### 18.8 坑：`vite build` 清不动满的 `dist`

`npx vite build` 在 `dist` 里有约 800 个文件时会失败（安全删除垫片拒批量删）。
`build-apk.sh` 里早写了这个坑，这次在**脚本外面手敲 `vite build`** 时又踩了一次。
➜ 手动重建也要先 `find dist -mindepth 1 -delete`。

## 十九、★ 这台机器推不上 GitHub（2026-09-22/23 实测）

**两道互相独立的墙**，任何一道单独都会让 push 失败，排查时别混。

### 19.1 墙一：出口代理的允许清单里没有 `github.com`

| 主机 | 走代理 |
|---|---|
| `api.github.com` | 200 |
| `codeload.github.com` | 301 |
| `raw.githubusercontent.com` | 301 |
| `gitee.com` / `bitbucket.org` | 200 |
| **`github.com`** | **000（CONNECT 被拒）** |
| `ssh.github.com` | 000 |
| `registry.npmjs.org` | 000 |

⚠️ **不是"代理在抖"**：curl 对 `github.com` 稳定 000、对 `api.github.com` 稳定 200；
**18 轮重试全 502**；绕过沙箱也无直连出口（`Could not connect ... after 21095 ms`）。
➜ `git-push-credential-stall` 里那套「耐心重试」在这里**不适用**，它是硬拦。
★ **判据：先分别 curl 一下 `github.com` 和 `api.github.com`。**
两个结果不一样 → 是按主机名拦，不是抖动 —— 别再重试了。

### 19.2 墙二：`~/.git-credentials` 里那个 token 是**别的账号**的

store 里唯一的 GitHub token（`gho_…`）属于 **luagioAI2**，
而目标仓库是 **stripluagio/little-writer-forest**：

```
permissions = {admin: false, maintain: false, push: false, pull: true}
```

**只有读权限。** 就算网络通了，也会是
`Permission to stripluagio/little-writer-forest.git denied to luagioAI2` + 403。
★ 这就是 skill「403 权限被拒」那一节：**能读不能写 ≠ 没权限，是拿错了账号。**
★ 一行查出来（不泄露 token）：

```bash
curl -s -H "Authorization: Bearer $TOK" https://api.github.com/repos/<owner>/<repo> \
  | python -c "import sys,json;print(json.load(sys.stdin).get('permissions'))"
```

### 19.3 顺带排掉的干扰项：`credential.helper` 是**多值**

本机是 `helper-selector` + `store` 两条，而 `helper-selector`（选中 `manager`）
是**交互式**的 —— 在非交互 shell 里**干等**，表现为「push 挂死 3 分钟没输出」。
➜ `git -c credential.helper= -c credential.helper=store push …`
（**先空值清空整个列表**，再挂 store；只写 `-c credential.helper=store` 是追加，前面那条照跑）。

### 20.4 家长另外要的那个「看旅行图的地址」

按距离筛选展示附近的旅游点、并**允许把旅游点编辑入库**。

⚠️ **尚未动工** —— 按 §九 的协作规则，先确认范围再动手。
可选项：① 一个只读的静态预览页（把 `LANDMARKS` + `TRAVEL_CONTENTS` 渲染出来）
② 带编辑/导出 JSON 的后台页（改完把 JSON 贴回代码）
③ 接一个能直接写库的本地服务。

### 20.5 家长拍板的方案（09-23）

| 问题 | 家长的决定 |
|---|---|
| 旅游点粒度 | 35 个太少（「中国的旅游点 只有这么点吗。就深圳一个地方 就一堆吧」）→ 要铺到**一两千个** |
| 铺什么 | **5A + 著名景点 + 游乐点**（点名了深圳世界之窗、海上世界） |
| 极限距离挂在谁身上 | **挂在鸟上**（八只鸟八档） |
| 档位怎么分 | 由近及远逐档推；后来把具体数值**交给我定** |
| 地图 | **分档切换** —— 前 7 档中国详图，凤凰档才拉远到世界 |
| 网页工具 | **预览 + 编辑导出 JSON**（不起服务） |

### 20.6 ★★ 机制设计：三条规则合成一个 for 循环

`src/domain/travelRange.ts`。半径阶梯是**倍增**的：

```
[25, 50, 100, 200, 400, 800, 1500, 3000, Infinity]
```

★★ **为什么不能按 20 公里等距加**：一两千个点摊到全国，平均每 6400 平方公里才一个，
最近邻普遍在 40–80 公里外。按 20 公里一档，**绝大多数档位是空的**，机制会一路空转到极限。
而半径每翻一倍，**圆面积翻四倍**，每档候选点数才大致相当。

★ **最小一格是 25 而不是 50**：要留住「就在家门口」那一档。深圳世界之窗离市民中心约 10 公里。

★ 鸟 → 能爬到第几格，与 `BIRD_SPECIES` 的解锁顺序一一对应：

```
麻雀 50 / 燕子 100 / 黄鹂 200 / 鸽子 400 / 喜鹊 800 / 蓝鸟 1500 / 仙鹤 3000 / 凤凰 ∞
```

★ **家长的三条规则就是那个 for 循环本身**：

```
for 每一格（由近及远，到该鸟极限为止）:
    pool = 这一格内的点，去掉已到访
    非空 → 随机挑一个
    空   → 下一格
都空 → exhausted
```

★ **`exhausted` 是独立返回值，不许"退回去随便挑一个"**：家长要的是「去过的不再访问」，
偷偷重复就违背了它。界面拿这个说「这只鸟能到的地方你都去过了，换一只飞得远的吧」——
这正好是推孩子去解锁下一只鸟的那句话。

### 20.7 ★★ 「X 距离已去完」是**算出来的**，不是存的

```
某个半径 r 已经去完  ⟺  r 公里内的每个旅游点都在「已到访」集合里
```

这与家长的描述**完全等价**，而且严格更好：

- 库新增一个点 → 它不在已到访集合里 → 该半径**自动复活**（家长要的）
- 老点仍然不在待选池里 → 不会被重复选中（家长要的）
- **零新增存档字段、零迁移** —— 避开 MEMORY §七 那类坑

★ 反面：如果真存一个布尔标记，就必须再存「这个标记是拿哪一版旅游库打的」，
否则库更新了也判断不出来 —— 反而多出一堆可能对不上的状态。
**能从既有数据推出来的，就不要存。**

★ 边界：**「这一档没有点」≠「这一档的点都去过了」**，`isRadiusExhausted` 对前者返回
`false` —— 两件事界面要说不同的话（「附近还没有地方可去」vs「附近你都去过了」）。

### 20.8 ⚠️ 连带影响：进度条要换口径

`mapProgress()` 现在拿 `LANDMARKS.length` 当分母。库扩到一两千之后
「已点亮 / 1500」永远停在 0.2%，**这个进度条就没意义了**。
进度得改成按**省份 / 国家**算（`exploredProvinces` 已经有了）。
★ 这是「库变大」的连带影响，不是新 bug —— 但改库的时候必须一起改。

### 20.9 数据与坐标怎么来（探测结果）

| 来源 | 可达 | 能不能用 |
|---|---|---|
| 高德 / 腾讯 / 百度 POI 接口 | ✅ 200 | 要 key；★ 地图厂商 POI 一般**不许离线打包再分发** |
| Wikidata / Nominatim / `www.openstreetmap.org` | ❌ 000 | 不可达 |
| **Overpass API（OSM 的查询接口）** | ✅ 200 | ★★ **可达 —— 但必须 POST**，见 §20.10 |
| Photon（komoot，免 key） | ✅ 200 | **只有城市级，没有景点级** —— 不够用 |
| GitHub API / raw | ✅ | 可达；★ **中文查询要 URL 编码**，★ **必须带 User-Agent**（不带会被代理挡成 HTML） |
| Wikipedia（走 WebFetch） | ✅ | ★★ **能拿到准确坐标** —— 已实测（深圳世界之窗 22.5350 / 113.96861） |

➜ **坐标走 WebFetch 查 Wikipedia 逐个核实，不靠记忆编。**

### 20.10 ★★ 更正：Overpass 是可达的（我判错过一次，记下来）

**§20.9 那张表原本把「OSM」记成不可达，是错的。** 错因只有一条：
**我只用 GET 试过。**

| 主机 | GET | **POST** |
|---|---|---|
| `overpass-api.de` | ❌ 406 | ✅ **200** |
| `overpass.private.coffee` | ❌ 400 | ✅ **200** |

★★ **判据教训（比结论更值钱）**：`406` / `400` 的含义是
**「这个方法/这个参数不行」**，**不是「这台主机不可达」**。
只有 `000` 才是不可达。
⚠️ 把 406 记成「不可达」，代价是**后面每一次都不会再试它** ——
一条错误的负面结论会自我复制。
➜ **规矩**：探测外部服务，**GET 失败必须再补一次 POST**（API 型服务尤其如此）；
记结论时要**把状态码一起记**，别只记「可达/不可达」。

### 20.11 Overpass 能拿到什么（广东实测）

`overpass-api.de` 数据是当天的（`timestamp_osm_base`）；
`overpass.private.coffee` 停在 2026-05，**优先用前者**。

```sparql
[out:json][timeout:180];
area["name"="广东省"]["admin_level"="4"]->.gd;
(
  node["tourism"~"^(attraction|theme_park|museum|zoo|aquarium)$"](area.gd);
  way["tourism"~"^(attraction|theme_park|museum|zoo|aquarium)$"](area.gd);
);
out count;
```

- ★★ **广东省 = 1976 个**（node 1173 + way 803）→ **一个省就够「一两千个」**。
- 深圳一个框（框跨到香港，所以混进港方条目）= **330 个带名字的**。
- 名字是真人会认的：`地王观光·深港之窗`、`邓小平塑像`、`东门`、`华强北`，
  以及世界之窗园内那一串 `富士山微缩模型` / `悉尼歌剧院微缩模型` / `自由女神像微缩模型`。
- ★ **`out count;` 只回计数**，是量规模最省流量的写法 —— 铺库前先量一下。

### 20.12 ⚠️ 用 OSM 数据前必须解决的两件事

1. ★★ **授权是 ODbL**（响应体里自己写着
   `The data is made available under ODbL`）。
   打包进 APK 需要**署名**「© OpenStreetMap 贡献者」，
   且衍生数据库**同样要开放**。
   ➜ **这是产品/法务决定，不是技术决定 —— 必须家长拍板**，
   不能因为"技术上跑通了"就直接铺进仓库。
2. **原始数据有噪声，两道过滤都要做**：
   - ★ `tourism` **不加值过滤会把酒店捞进来**（`tourism=hotel`）——
     第一次试查的 8 条里 5 条是酒店。
   - 加了值过滤之后，仍混着**观景台 / 微缩模型 / 雕像**这类
     「景点内部的小件」→ 入库前还要按名字 + 是否园内子件再筛一轮。

### 20.13 另外两条被否掉的路（省得重走）

- **DBpedia SPARQL**（`dbpedia.org/sparql`）**可达**，但：
  按 `dbo:TouristAttraction` + `dbr:China` 查 → **0 条**；
  退成纯经纬度框查 → 回来的是**行政区 / 车站 / 机场**，
  甚至捞到 `天问一号`、`祝融号火星车`。
  ➜ **它是通用地理实体库，不是景点库，用不了。**
- **Wikipedia `list=geosearch`** 能一次批量返回带坐标的条目，但
  ★★ **`gsradius` 上限就是 10 公里**（超了直接 `outofrange` 报错）
  → 只够城市核心；要铺全省得按城市切很多次。
  另外：`中国国家5A级旅游景区` 列表页**有名字没有坐标**；
  `深圳市旅游景点列表` 这一页**根本不存在**（别照着记忆去 fetch）。

## 二十一、广东景点库：从 OSM 生成（09-23）

家长拍板「**OSM 批量 + 署名**」「**第一批铺广东全省**」。

### 21.1 一句话结论

**能拿到量**（广东一个省 2037 个候选），
**但自动过滤的精度上限大约 60~70%** —— 剩下的必须靠人或靠网页工具剔。
这两句都要记住：只看前者会以为问题解决了，只看后者会以为这条路走不通。

### 21.2 ★★ 授权是 ODbL —— 所以数据**分两个文件**

- `landmarks.json`（手工精选）+ `landmarks-gd.json`（OSM 生成）**故意不合并**。
  ➜ 合并之后就**再也说不清哪些条目受 ODbL 管**。
- ★★ **许可与署名跟着数据走**：生成文件**不是裸数组**，而是
  `{ license, source, attribution, generatedBy, count, items }`。
  谁把数据复制走，抬头就跟着走，不会只剩一堆坐标。
- ★★ App 里必须署名「**© OpenStreetMap 贡献者**」（设置页「关于」），
  并在 `_verify-apk.mjs` 的 `FEATURES` 里加了一条守着 ——
  **法律要求不许在打包时被丢掉**。

### 21.3 ★★ 必须转坐标系：OSM 是 WGS-84，我们库里是 GCJ-02

国内两者差 **300~600 米**，而且**偏移量随经纬度变化**（不是整体平移，改不回来）。
不转 = 整个库系统性偏移。所以脚本里显式 `wgs84ToGcj02()`，
**国外坐标原样返回**（`outOfChina`）—— 这也让将来混入世界景点是安全的。

### 21.4 原始数据有四类噪声，对策各不相同

| 噪声 | 实测 | 对策 |
|---|---|---|
| **酒店** | 第一次试查 8 条里 5 条是酒店 | `tourism` **必须按值过滤**（`hotel` 不在白名单） |
| **山峰** | 深圳一个市 **550 个**有名山峰（三角山、求水顶…） | 只留名字在 `PEAK_ALLOW` 里或带 `wikidata` 的 |
| **道路设施** | `historic=ruins` 里是 `沃尔玛`、`盐田综合车场`、几十个 `XX收费站` | `ruins` **整类不要**；再加名字黑名单 |
| **园内小件** | 世界之窗内有 20 来个 `tourism=attraction`（`长城模型`、`猴园`） | ★★ **点在母体多边形内就剔掉** |

★★ **园内小件这一条是最容易漏、后果最坏的**：不剔的话孩子会
「去世界之窗二十次」。而且**只查 `theme_park` 不够** ——
`大鹏所城` 里的 `赖恩爵振威将军第`、公园里的 `碧岸观山` 照样漏进来
（实测深圳 238 条里近一半是这种）→ 母体要把
**公园 / 风景名胜 / 古迹**的多边形一起拿。

⚠️ 做点在多边形内时**必须排除"自己包含自己"**：
`out center` 给的重心**一定落在自己的多边形里**，不排除的话
`大鹏所城` 会把自己筛掉，整条消失。

★ **名字过滤要用「词尾」而不是「词」**：
`繁花谷`/`礼贤台`/`望龙坡`/`兰花溪` 这些字**只有做结尾时才表示"园里一个造景点"**。
按词尾挡，`华强北`/`京基100`/`明华轮`/`大芬油画村` 就不会被误伤。
⚠️ 刻意**不挡** `园`/`馆`/`寺`/`庙`/`塔`/`桥`/`祠`/`碉楼`/`温泉` ——
`陈家祠`、`广济桥`、`开平碉楼` 都靠它们活着。

### 21.4.1 ⚠️⚠️ 这张词尾表**越长越危险**（欢乐谷被误杀）

加「最知名的」闸门之前，我为了压噪声把词尾表加到了 30 多个字，
**结果把 `欢乐谷` 挡掉了** —— 深圳最有名的游乐点之一。
同一批误伤还有：`池`→`长白山天池`、`陵`→`明十三陵`/`黄帝陵`、
`亭`→`兰亭`/`醉翁亭`、`谷`→`东部华侨城-茶溪谷`/`大侠谷`。

★★ **根因**：我在**用名字规则去干"出名度"的活**。
`繁花谷` 之所以是噪声，**不是因为它叫"谷"，而是因为它没名气**。
出名度闸门一上，`繁花谷`/`昆虫谷` 自己就没了（没有 wikidata），
**名字规则就该退回去只做它擅长的事**。

➜ **判据**：一条过滤规则，如果它挡掉的东西**靠另一条更准的规则也能挡掉**，
那它就是纯风险 —— **删掉它**。
现在 `SUFFIX_BAD` 只剩 12 个字（`阶|澜|圩|音|蛋|梗|坳|眼|碧|宾|灘|灣|嶼`）。

⚠️ 教训的通用形状：**为了压一个噪声，把规则调狠，代价是杀掉真数据；
而真数据被误杀时不会报错 —— 它只是"不在列表里"。**
所以每次收紧规则后，**要去名单里找那几个"应该在"的名字**，
而不是只看总数变小了、看着挺干净。

### 21.5 ⚠️ OSM 里**市界本身**也有错 —— 只能手工列

`惠东大南山` 的坐标是 (22.9236, 114.9259)，在惠州惠东，
离深圳市民中心 **98.6 公里** —— 但它**通过了 Overpass 自己的
`area["name"="深圳市"]` 过滤**。

★★ **推论**：错的是 **OSM 的市界多边形**，不是我们的判定。
所以**"再拿同一份边界去验点在不在多边形内"是无效的** ——
会继承同一个错误。（本来想这么做，做到一半发现，放弃。）
➜ 改成 `MISPLACED` 手工表 + 「离本市中位数中心 >120 公里」兜底。
⚠️ 这是唯一一处人工干预，**每加一批城市要回看一眼**。

### 21.6 Overpass 的工程细节（都是踩出来的）

- ★★ **必须 POST**。GET 一律 406/400 —— 见 §20.10。
- ★★ **一台实例会连续 504**（`server is probably too busy`，
  实测广州市连试 5 次全挂），**换一台立刻就通**。
  ➜ `ENDPOINTS` 数组，**每次重试换一台**；主站优先（备用实例数据旧：
  实测 private.coffee 停在 2026-05，主站是当天）。
- ★★ **客户端超时必须有**（`AbortSignal.timeout`）。
  实测备用实例会**挂住不动**（一次请求卡 75 秒以上）；
  查询里写的 `[timeout:180]` 是**服务端的**执行上限，
  **拦不住"连上了但一直不回"**。没有这一行，一个挂死的实例
  能把整个抓取拖到天荒地老。
- ★★★ **HTTP 200 ≠ 有数据** —— 这条差点让我选错实例。
  `overpass.osm.ch` 用真实城市查询返回 **200，耗时 1.3 秒，但元素数 0**。
  它是**瑞士**的区域实例，**根本没有中国的数据**。
  ➜ 判据必须是**「元素数 > 0」**，不是状态码、更不是"快"。
  ⚠️ 我第一轮探测就是只看状态码，把它的 200 当成了可用信号。
- ★ 可用的实例（2026-09 实测）：**只有** `overpass-api.de`（忙时 504）
  与 `overpass.private.coffee`（有中国数据，但慢/会挂）。
  以下全部 **000 不可达**：`overpass.kumi.systems`、`overpass.osm.jp`、
  `maps.mail.ru`、`overpass.openstreetmap.ru`、
  `overpass-api.openstreetmap.fr`、`overpass.osm.rambler.ru`、
  `overpass.nchc.org.tw`。
- ★ **一条大 union 会 504，拆成三条小查询就好很多**，
  而且**一类挂了另两类还在** —— 代价是少几条，不是整座城没有。
- ★ 单个市失败**不许中断整个抓取**：软失败 + 最后**显式列出没抓到的市**。
  ⚠️ 不列的话，库会「少几个市但看起来完全正常」，孩子飞过去发现附近没地方，
  而日志里什么都没说。
- ★ **先 `out count;` 量规模**再决定怎么抓 —— 只回计数，最省流量。
- ★ **缓存放 `node_modules/.cache/overpass/`**（本来就被 gitignore），
  重跑不重复请求。**改过滤规则不会让缓存失效**（缓存的是原始响应，这是对的）。
  ➜ 也因此**抓取是"可续跑"的**：中断了再跑会接着来，不会白跑。
- ★★ **同时跑 2 个市**（不是 1 个，也不是 8 个）。
  实测**几乎每次首轮请求都失败**，全靠重试才通，一个市平均 3.5 分钟，
  而**大半时间在等退避、不是在传输** → 并行两个市把等待重叠掉，时间大致减半。
  ⚠️ **只开 2 路**：Overpass 是公共资源，开太多会把别人挤下去，
  也会招来更多 504。市之间没有共享状态，所以并行是安全的。
- ★★ **"改查询"必须同时换缓存键或清缓存**。
  缓存键是 `标签-城市`，标签没变 → 会**命中上一次旧查询的结果**，
  表现是"我明明改了过滤条件，输出却没变"。这次是靠 `rm -f` 清掉躲过去的。
  ⚠️ 这条很容易骗过自己：脚本"成功"了、文件也写了，只是内容是旧的。

### 21.7 scene 推断的顺序坑

`塔`/`古城`/`牌坊` 原来和 `寺`/`庙` 放在同一条规则（temple），
结果 **`广州塔` 会被判成"寺庙"配色**。
➜ 现代塔、古城街区、牌坊街都归 `city`；temple 只留**宗教与宗祠**类。
（同一类坑在 §四 记过一次：**规则表的顺序本身就是判定的一部分**。）

### 21.8 ★★ 家长定的规模口径：≤3000 / 中国 2000 / 只要最知名的

家长看完数量后拍板：「**数量太多了**。加上世界总数**不能超过 3000**。
中国 **2000** 个点差不多了。**最知名的**。」

➜ 判据：**有 `wikidata` 或 `wikipedia`**（出名到有人给它建百科条目），
**或者**是 `theme_park`/`zoo`/`aquarium`（本身就是"值得专程去"，且量很少）。

实测效果（同一批数据）：

| | 不加闸门 | 加闸门 |
|---|---|---|
| 深圳 | 131 | **47** |
| 广州 | 296（有名）/ 87（并集） | **~87** |

★★ **这个闸门是"顺手"的：它同时把三件事一起解决了**
① 量降到家长要的口径；② 精度从 ~65% 提到 ~85%；
③ **单次查询从 1447 条降到 113 条**，Overpass 也就不那么容易 504 了。
➜ 说明"量太大"和"质量差"在这个数据源上是**同一个问题**。

⚠️ **别用 Overpass 的键正则** `[~"^(wikidata|wikipedia)$"~"."]`：
实测它慢得多、更容易 504。**写成 `["wikidata"]` / `["wikipedia"]` 两条**即可。

⚠️ 闸门**同时写在服务端和客户端**：服务端是为了少拉数据，
客户端是为了**换数据源时行为不变**（双保险）。

## 二十二、★★ 被判断的字符串 ≠ 被存下去的字符串（09-23 实测）

> 两个**同源**的缺陷，都是"守卫写了、跑起来却什么都没做"。
> 共同点：**没有任何报错、没有崩溃、计数还是 0** —— 看上去像"数据本来就干净"。

### 22.1 归一化排在了判据后面

**现象**：`李众胜堂祖铺李众胜堂祖铺` 明明写了守卫，还是进了库。

**真相**：OSM 里这个元素的原始 tag 是

```
name = "李众胜堂祖铺 李众胜堂祖铺"      ← 中间夹了个空格，raw 长度 13
```

而落库前会 `key = name.replace(/\s+/g, '')` → **12 字，正好是自身两遍**。

于是：

| | 用的字符串 | 长度 | 判据结果 |
|---|---|---|---|
| 重复名守卫（写在前面） | raw `name` | 13（奇数） | **不成立** → 放行 |
| 落库（写在后面） | `key` | 12 | 正好两遍 |

★★ **被判断的字符串 ≠ 被存下去的字符串** —— 守卫整条失效。

**改法**：把 `const key = name.replace(/\s+/g,'')` **提到所有名字判定之前**，
后面**全部判定与落库都用 `key`**。

**一般化**：
- ★★ **归一化只做一次，且必须排在所有判据之前**；判据与落库**读同一个变量**。
- ★★ **改完守卫必须看那条计数从 `0` 变成非 `0`** ——
  这次 `badName` 从 26 → 27，才证明守卫真的活了。**计数没动 = 等于没改。**

### 22.2 守卫写好了，但测试没跑

那条「生成侧名字不许被写了两遍」的测试**早就写好了**，位置也对。
问题是**加完测试没跑** —— 于是它红着，而数据已经落库、已经过了 build。

★★ **写完守卫立刻单独跑一遍它的测试**（`npx vitest run <那个文件>`）。
**"测过了"和"测试存在"是两件事。**
⚠️ 全量跑一次要 57 秒，很容易"等会儿一起跑" —— 而那正是漏掉的窗口。

### 22.3 ★★ 跨市去重：市内 `seen` 挡不住跨市重复

**现象**：`checkLandmarks` 报 **id 重复**；`sproutCount` 比 `LANDMARKS.length` **少 2**。

**真相**：`area["name"="深圳市"]` 用的是 **OSM 自己的行政边界**，而那份边界**本身有错**
（§21.5：`惠东大南山` 离深圳 98.6 km 却通过了深圳的 area 过滤）。
边界一重叠，边界附近的地物就**同时**进两个市的候选：

```
翔顺飞天蚕旅游度假区  江门 / 云浮   （实际在云浮新兴）
石人山               深圳 / 汕尾   （实际在汕尾，lng 115.0）
```

`filterCandidates` 里的 `seen` 是**每个市一份**的 → 跨市看不见对方 → 同一个 `osm` 落库两次。

★ **判据：留"几何上最近的"那个市，而不是"先来先得"**。
先来先得会把 `石人山` 算进深圳。做法是先用各市自己的点算质心，再比距离。

⚠️ 这个 bug 的**症状离原因很远**：报的是"id 重复"，根因是"OSM 边界错"。
➜ 所以 §21.5 那条（"别信 OSM 的市界"）不是一次性的，**它会以别的形态再回来**。

### 22.4 本轮验证

- `npm run lint` → **0 error / 8 warning**（基线未动）
- `npx vitest run` → **35 files / 722 passed + 10 skipped = 732，0 failed**
- 广东库：301 → **298 条**（重复名 −1、跨市重复 −2）
- 佛山单市复验：40 → 27 → **26**（`badName` 26 → 27）

## 二十三、★★ 「同一个守卫只装了一半」—— 评级（5A/4A）的同名不同地（09-23）

### 23.1 家长指令

> 「一线 城市 最多 10 个，二线 最多 5 个。还得是全国知名的。另外还要评级。」

### 23.2 名单的**形状**决定了守卫能装在哪

外挂名单 `scripts/gd-a-level.json`：

```jsonc
{ "5A": [ { "name": "广州长隆旅游度假区", "city": "广州" }, ... ],   // 16 条，带 city
  "4A": [ "白水寨风景名胜区", "观音山旅游风景区", "莲花山旅游区", ... ] }  // 172 条，纯字符串
```

**5A 带 `city`（16/16），4A 不带（0/172）。** 当时加 `city` 只是为了**城市归属**
（罗浮山的多边形质心离东莞更近，官方说它在惠州）和 **5A 的距离守卫**。

★ **但 `ratingOf()` 是两个分支**：

```js
function ratingOf(name, lng, lat) {
  const five = official5A(name, lng, lat)          // ← 有 150km 守卫
  if (five) return five.misplaced ? undefined : five.level
  const c = coreName(name)                          // ← 以下全是裸查表，没有守卫
  if (RATING_LOOKUP.has(c)) return RATING_LOOKUP.get(c)
  const viaAlias = SCENIC_ALIAS[c]
  if (viaAlias) return RATING_LOOKUP.get(coreName(viaAlias))
  for (const [core, level] of RATING_LOOKUP) if (scenicMatch(c, core)) return level
  return undefined
}
```

➜ **"同名不同地"的守卫只装在了 5A 那一支上。4A 是裸查表。**

### 23.3 后果（实测）

| 名单里的 4A | 真实所在 | 被谁继承了 |
|---|---|---|
| `莲花山旅游区` | 广州番禺 | 东莞·莲花山、惠州·莲花山、江门·莲花山、汕头·莲花山(汕头)、东莞·莲花山旅游区 |
| `观音山旅游风景区` | 东莞樟木头 | 惠州·观音山、清远·观音山、韶关·观音山、深圳·观音山公园 |
| `白水寨风景名胜区` | 广州增城 | 东莞·白水寨风景名胜区、东莞·白水寨景区 |
| `莲花山旅游区` | 同上 | 东莞·莲花山水库 |

**约 13 / 68 条 4A 是"继承"来的（~19%）。**

⚠️ `coreName()` 把 `莲花山旅游区` 削成 `莲花山` —— **削掉的正是区分"哪一个莲花山"的那个词**。
所以「精确命中」这个桶里也混着跨市泄漏：`东莞·莲花山` 的 core 就是 `莲花山`，
它**精确命中**了番禺那条 4A。

### 23.4 ★ 教训

1. ★★ **一个判据只要有多条实现路径，守卫就必须每条都装。**
   这与 §五「一个设置项有多条执行路径，就必须每条都读」是**同一条**，
   只是换了个面：那次是**读**漏了，这次是**守卫**漏了。
2. ★★ **名单的"形状"本身是隐患**：`5A` 是对象数组、`4A` 是字符串数组 ——
   形状不一致，所以**能装的守卫也不一致**。要么统一形状，要么明确记下"哪条路没守卫"。
3. ★ **`coreName` 削后缀 = 主动丢掉区分度**。它解决了 `广州市白云山风景区`→`白云山`，
   但也把 `莲花山旅游区`/`莲花山公园`/`莲花山水库` 全并成 `莲花山`。
   ➜ 削后缀的匹配**必须再有一道位置/城市校验**兜底，不能单靠名字。
4. ★ **和 §14.3 的 `万绿湖` 是同一个病**：那次是**远距离**（160km）误判，这次是**中距离**
   （20–70km）误判。**同一个病会以不同距离尺度回来。**

### 23.5 另一类：城市归属错（与评级无关）

`白水寨`（113.76/23.59）行政上属**广州增城**；`东莞·莲花山旅游区`（113.50/22.99）是**番禺**的。

根因：**最近 `CITY_SEAT` 判定**。增城在广州市区**东北 70km**，而离东莞 seat 只有 **63km**。

⚠️ 全省「离本市中心 >60km」的条目 **0 条** —— 所以**不是** `万绿湖` 那种远距离误判，
而是 **seat 是"点"、市界是"面"** 的固有误差。
➜ 修法得用**真实市界多边形**（或官方 5A 那种"名单自带 city"），**不是调半径**。

### 23.6 待家长定的三件事（**都没动**）

1. **4A 也补 `city`**，走同一个 `official5A` 守卫（约 13 条会被摘掉评级）。
2. **重复簇要不要收**：江门 41 条大半是开平碉楼子楼（三线市按规则**不设上限**）；
   东莞 `莲花山`/`莲花山旅游区`/`莲花山水库` 一山三名 + `白水寨`×2；广州 `白云山`×2。
3. **5A 铺成 20 条**（官方只有 16 家）：白云山×2、长隆×4、丹霞山×2、孙中山故居+故里×2。

## 二十四、★★ 距离守卫挡不住「密集城市群」—— 评级张冠李戴（09-23）

### 24.1 病根不在守卫写错了，在**名单的形状**

```jsonc
// 改之前
{ "5A": [ { "name": "...", "city": "广州" }, ... ],   // 对象数组，16 条，带 city
  "4A": [ "广州塔", "白水寨风景名胜区", ... ] }        // 纯字符串，172 条，不带 city
```

`ratingOf()` 于是有**两条不等价的支**：

```js
const five = official5A(name, lng, lat)        // ← 有 150km 距离守卫
if (five) return five.misplaced ? undefined : five.level
const c = coreName(name)                        // ← 以下全是裸查表
if (RATING_LOOKUP.has(c)) return RATING_LOOKUP.get(c)
...
```

➜ **「同名不同地」的守卫只装在 5A 那一支上。**

### 24.2 ★★ 但真正的坑是：**150 km 这个阈值对珠三角毫无意义**

装守卫的时候，参照系是那一次踩的坑 —— 广州有个 `natural=water` 的湖也叫`万绿湖`，
**离河源 160 km**，所以「同一个景区不可能离自己的市 150 公里」成立。

**换到 4A 就崩了**：

| 名单里的 4A | 真实所在 | 撞名的元素 | 离名单那座城市 |
|---|---|---|---|
| `莲花山旅游区` | 广州番禺 | 东莞·莲花山 | **64 km** ✅ 轻松过关 |
| `观音山旅游风景区` | 东莞樟木头 | 深圳·观音山公园 | 85 km ✅ |

**东莞那座莲花山离广州市区只有 64 公里。** 150 km 的阈值不可能挡住它 ——
它们本来就是**两个相邻的市**。

★★ **教训**：装一个"距离守卫"之前，先问
**「两个不同地方、同一个名字，最近能有多近？」**
如果那个距离**小于**你的阈值，距离就是错的判据 —— 你要的不是"远近"，是**身份**（城市/行政边界）。

➜ 最后用了**两道**：距离挡远距离张冠李戴，**城市相等**挡近距离的。

### 24.3 ★★ 归一化会**主动丢掉区分度**

`coreName()` 的活是"把官方写法和 OSM 写法对齐"：
`广州市白云山风景区` → `白云山`、`佛山市西樵山景区` → `西樵山`。

但它同时把 **`莲花山旅游区` / `莲花山公园` / `莲花山水库` / `莲花山` 全并成 `莲花山`** ——
**削掉的正是"哪一个莲花山"**。

⚠️ 所以「精确命中」这个桶里也混着跨市泄漏：`东莞·莲花山` 的 core 就是 `莲花山`，
它**精确命中**了番禺那条 4A。**光看"精确命中"的比例会被骗。**

★★ **教训**：**任何"削后缀"的匹配，都必须再有一道位置/身份校验兜底，不能单靠名字。**
削后缀是为了**召回**，不是为了**判等**。

### 24.4 ★★ 「按名字抓 + 按 seat 猜城市」在珠三角**必错**

整省「按名字抓」的元素没有行政归属，只能按"离哪个市政府最近"分下去。
实测错的（**离本市市区 26–85 km，而两个市府之间常常只有 30–50 km**）：

| 条目 | 实际属 | seat 猜成 | 为什么 |
|---|---|---|---|
| `宝墨园` / `沙湾古镇` | 广州（番禺） | 佛山 | 番禺在广州市区正南 26 km，离佛山市区 23 km |
| `白水寨风景名胜区` | 广州（增城） | 东莞 | 增城在广州市区东北 72 km，离东莞市区 63 km |
| `广州融创水世界` | 广州（花都） | 清远 | 33 km vs 34 km —— **差 1 公里** |
| `皂幕山旅游风景区` | 佛山（高明） | 江门 | 48 km vs 35 km |
| `泉林黄金小镇` | 江门（恩平） | 阳江 | 85 km vs 53 km |
| `海上田园` | 深圳（宝安） | 东莞 | 36 km vs 33 km |

★★ **修法不是调半径** —— 广州从化/增城离市区 70–90 km、江门恩平离市区 85 km，
半径调大了会把隔壁市的全收进来。**修法是拿到真实市界**（或官方名单自带的城市）。

➜ 本次的做法：**名字「完整覆盖」官方名时（覆盖度 = 1），官方城市说了算。**

```js
function nameCoverage(official, element) {   // 用**原始名**算
  if (e.includes(o)) return 1                 // `白水寨风景名胜区` vs 官方同名 → 1.0
  ...                                          // `莲花山` vs `莲花山旅游区` → 3/7
}
function fullyCovers(name) {                   // 只有 1.0 才返回
  const hit = ratedAreaFor(name)
  return hit && nameCoverage(hit.name, name) === 1 ? hit : null
}
```

★★ **必须用原始名，不能用核心词**：`莲花山` 与 `莲花山旅游区` 的**核心词都是 `莲花山`**。
用核心词 → 东莞那座山也拿 1.0 → 被搬进广州（实测过）。

### 24.5 ★ 副作用：**归属一修对，上限就开始吃人**

把 4 个地方正确地归进广州之后，广州的 **10 个名额**就把它们挤掉了：
`白水寨`、`宝墨园`、`沙湾古镇`、`广州融创水世界` **从库里消失**。
而 10 个名额里 **4 个是长隆的园**（欢乐世界/野生动物世界/水上乐园/飞鸟乐园）。

⚠️ 同理，官方 **163 家 4A 里库里只评上 53 家** —— 110 家被广州/深圳/佛山/东莞的上限截掉，
含 `广州塔`、`越秀公园`、`黄埔军校旧址`、`北京路步行街`。

★★ **教训**：**"按城市设上限"和"按景区去重"是一对** ——
只要上限在，"同一个景区占几个名额"就直接决定谁被挤出去。
先定去重口径，再定上限，否则上限会替你做一个你没意识到的选择。

### 24.6 ★ 排名兜底是**字母序**，等于让名字决定谁进库

`rankOf` 同分时 `a.name.localeCompare(b.name,'zh')`。
实测 `广州塔`（4A + 15 分孩子想去）输给 `广东科学中心`（4A + 25 分）**10 分** →
广州塔落选。⚠️ 这种"差一点点"的落选**不报错、日志里也不显眼**，
只是"库里没有广州塔"。

### 24.7 ★ 两条工程细节（踩了就浪费半小时）

1. ★★ **vitest 下不能用 `import.meta.url` 取路径**：
   vitest 用虚拟 URL 提供模块，`new URL(...)` / `fileURLToPath(...)` 会抛
   `The URL must be of scheme file`。用 **`join(process.cwd(), ...)`**。
   ⚠️ 另外这里的 fs 是**沙箱代理过**的，喂 `URL` 对象也会报同一个错。
2. ★ **`sed` 做变异时用 `trap ... EXIT` 还原**，否则中途失败会把产物留在变异状态。
