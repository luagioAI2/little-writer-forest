# 2026-10-03

## 网页 / 桌面：不接云端转写，改成把话说清楚

家长原话：「可不可以区分 APK 和 web。手机按最好体验。」→ 我先答「区分已经在了（`isStreamingSupported()` 一处判据）」→ 家长追问「网页是不是本身就可以通过输入法的语音输入的。」→ **对**，于是定案：

- **网页不接云端转写。** 写作页本来就有键盘入口（`VoiceComposer.tsx` 的「不方便说话？用键盘输入」），系统/输入法自带的语音输入（Windows `Win+H` / macOS 听写 / 手机输入法麦克风）能直接打进那个框 —— 比接火山 REST 更快、不花钱、不暴露密钥、不用维护代理。**上一轮我提的「给网页接火山 REST 整包上传」作废。**
- **手机 App 侧一个字没动** —— 还是流式按住说话 + 进页面预热。家长要的「手机按最好体验」本来就是现状。

### 改了什么（两处源文件）

1. `src/components/VoiceComposer.tsx` —— 键盘入口外面包一层 `flex flex-col items-center gap-2`，并在 `!isStreamingSupported()` 时补一句说明：「这台设备没有云端语音转写，语音输入请在手机 App 里用。／ 也可以打字，或用输入法自带的语音输入（Windows 按 Win+H）。」
   - ★ 判据用 `isStreamingSupported()` 而**不是** `!canTranscribe` —— 后者在「APK 忘打密钥」时也为假，而那种情况在手机上，提示会指错方向。
   - ★ 这段在 APK 上**恒不渲染** → 不增加任何高度 → 碰不到「按下时按钮一动都不动」那条红线。
   - 新增 `import { isStreamingSupported } from '../platform/ws-transport'`。
2. `src/platform/speech.ts` —— `network` 那条文案从「语音识别需要联网，请检查网络」改成「语音识别连不上：可能是断网，也可能是浏览器自带的识别服务在当前网络下用不了」。**旧文案把"墙"说成"你网不好"，家长会去查路由器。**
