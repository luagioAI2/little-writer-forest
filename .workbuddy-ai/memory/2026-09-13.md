## 旅行内容包 v5 —— 照片预显示

用户反馈「长城图片不能正常显示」，排查后发现不是 URL 问题（Unsplash 返回 200，262KB），而是之前的设计规则：真实照片和散文只在「小鸟真的飞过去并带回来」之后才显示。全新存档里麻雀还没出过门，所以看到的是 `LandscapeArt` 程序化插画。

用户确认「显示」—— 意思是照片应该立刻显示，不需要等鸟飞回来。

### 修改内容

**`src/features/map/MapPage.tsx`**
- `LandmarkSheet` 新增 `collected: boolean` prop（小鸟是否真带回过照片）
- `story`（内容包）无条件传递 —— 有内容包就显示照片
- 照片（`TravelPhotoFrame`）始终显示 `story?.photoUrl`，不受 `collected` 限制
- 文案分支根据 `collected` 切换：
  - `true`：「小鸟在这里带回过照片」+ summary + 相册入口
  - `false`：「这里有一张照片等着小鸟去拍」+ 派鸟引导
- `pickedStoryDistance` 不再受 `photoPoints.has()` 限制 —— 距离是地标属性，有内容包就显示

**设计意图**
- 照片 =「这个地方长什么样」的预告，点开就能看到，方便用户核对内容包数据
- 散文 = 小鸟的游记，只有真去过才给，保留探索感
- 地图金环 + 相册记录仍然只认「真的带回来过」

### 验证结果

- `npm run lint`：0 error / 7 warning
- `npm test`：10 files, 194 passed
- `node scripts/_verify-travel-photo.mjs`：28/28 通过
- 在线：照片正常加载（naturalWidth > 0）
- 离线：fallback SVG 插画正常显示，不崩不白屏

**后续**
- 真浏览器验证新增「没派鸟就能看到照片」断言（29/29 通过）
- 用户反馈最开始浏览器里还是没看到，确认是旧缓存；强制刷新后正常显示

## 旅行系统 v6 —— 小鸟随便飞 + 阅后即毁

用户提出大改：
1. 内容包提供独立经纬度，小鸟随便飞（不绑定地标）
2. 同一个地标可配多条内容（多图/多散文）
3. 地标只是标记，只有到过的地方才能点亮（播撒种子）
4. 种子产生概率降低
5. 小鸟带回多种内容：照片、音乐、笑话、视频、格言、故事
6. 阅后即毁模式：24 小时后消失，50 金币可永久保留

- 新增 `TravelContentType` = 'photo'|'music'|'joke'|'video'|'quote'|'story'
