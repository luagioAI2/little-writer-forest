# 2026-10-04

## 一、★★★ 事故与恢复：`git filter-repo` 把整个 `.git` 弄没了

**背景**：家长要「改用 GitHub Release 存包」，并同意「重写历史清掉」那两个 APK blob
（`website/download/xiaobimiao-android.apk`，2 个 blob ≈ 18MB，占仓库 85%）。

**怎么炸的**：
```
git filter-repo --force --path website/download/xiaobimiao-android.apk --invert-paths
→ Parsed 19 commits / HEAD is now at c1cc4d3 / New history written in 4.44 seconds
→ fatal: not a git repository (or any of the parent directories): .git
→ fatal: running 'git gc --prune=now' failed!
```
收尾的 `git gc` 失败后，`.git` 只剩 `objects/`（**1.0K，空的**）和 `info/`；
`HEAD`、`refs/`、`config`、`index` 全没了。filter-repo 的工作方式是
**把原 `.git` 挪到临时目录、再建一个新的**，最后一步崩了 → 临时目录也一起没了。
**新的历史（c1cc4d3）找不回来**，因为对象根本没落盘。

**救回来的关键**：动手前打了 `git bundle create ../_lwf-backup/lwf-before-purge.bundle --all`
（21,452,589 字节，`refs/heads/main = c82d4eb8`，18 commits）。**这一步救了全部历史。**
➜ ★★ **凡是会重写历史的操作，先 `git bundle create`，并且 `git bundle verify` 确认。**

**恢复过程（可直接抄）**：
```bash
# 1. 工作区是完好的（filter-repo 只碰 .git），先把改动存出来
cp website/index.html ../_lwf-backup/index.html.kept
cp .gitignore        ../_lwf-backup/gitignore.kept
# 2. 在**项目目录内**重建仓库（见下面那条沙箱坑）
cd <repo> && git init -q -b main
git remote add origin https://github.com/luagioAI2/little-writer-forest.git
# 3. bundle 拷进项目里再 fetch —— git 拒绝 fetch 进「当前已检出的分支」
cp ../_lwf-backup/lwf-before-purge.bundle ./_restore.bundle
git fetch -q ./_restore.bundle 'refs/heads/main:refs/remotes/bundle/main'
#    ⚠️ 这一步 exit=0 但**不一定建出 ref**；对象会进 pack，靠 .git/FETCH_HEAD 拿 hash
cat .git/FETCH_HEAD          # → c82d4eb8... branch 'main' of ./_restore.bundle
# 4. 用 hash 直接 reset（顺带把工作区还原成 c82d4eb8，APK 也回来了）
git reset --hard c82d4eb8b50732186d5835bcdf0c2f3b3c4f8280
# 5. 恢复配置（新 .git 的 config 是空的）
git config core.autocrlf true
git config --local credential.helper ""      # 空值 = 清空列表，压掉慢的 helper-selector
git config --local --add credential.helper store
# 6. 把第 1 步存出来的改动拷回来，重新提交
```

**★ 沙箱坑**：**工作区外的写入会被静默丢掉**。
`git clone` 到 `../_lwf-restore` 时，工作区文件落了盘、**`.git` 没有**；
`rm -rf ../_lwf-restore` 直接失败（`&&` 链第一环就断 → 整条命令**零输出**，
很容易误判成「什么都没发生」）。
➜ **一切 git 操作都在项目目录内做**；需要外部文件就 `cp` 进来。
➜ 排查时用 `;` 而不是 `&&`，保证每个 `exit=$?` 都打出来。

**教训**：`git filter-repo` 在本机（Windows / Git-Bash / MSYS 路径）**不可靠**。
下次要清历史，优先 **内置 `git filter-branch`**（它把旧 refs 留在 `.git/refs/original/`，
有安全网；不像 filter-repo 那样整目录替换）。
**本次没有重试清历史** —— 仓库已恢复到干净可用状态，清历史的事留给家长拍板。

## 三、平板适配（家长要求「适配支持下平板」）

**方法**：走 `tablet-layout-adaptation` skill —— **先量再改**。
新写了 `scripts/_probe-tablet.mjs`（puppeteer-core + Chrome，量 5 项：内容列宽/占比、
横向溢出、底栏占比、点击区、外壳宽）。支持 `E2E_ONLY=1366` 只量一档（做快速 A/B）。

**量出来的病根**：外壳 `App.tsx` 是 `max-w-2xl` = **672px，恒定**，
所以 1366×1024 上内容只占 **49%**，而且**顶栏/底栏也被卡在 672**（中间悬着一条横条）。

| 视口 | 改前 | 改后 |
| --- | --- | --- |
| 768×1024 | 672 / 88% | 672 / 88%（不变） |
| 1024×768 | 672 / 66% | 896 / **88%** |
| 1024×1366 | 672 / 66% | 896 / **88%** |
| 1366×1024 | 672 / **49%** | 1024 / **75%** |
| 1280×800 | 672 / 53% | 1024 / **80%** |
| 手机 390 / 414 | 100% | 100%（**不变**） |

**改法**（关键判据都在注释里了）：
1. `theme.css` 加 `.page-col`：base `42rem`（= 原 `max-w-2xl`，手机与竖屏平板**零变化**）、
   `≥1024 → 56rem`、`≥1280 → 64rem`。
   ★ 写成**无 layer 的普通 CSS**（不是 `@utility`）：无 layer 优先级高于任何 `@layer`，
   才能压住页面里残留的 `max-w-*`。写成 `@utility` 会同层，谁生效只看样式表顺序。
2. `App.tsx`：外壳去掉 `max-w-2xl` 变通栏；顶栏内层 / **`<main>`** / 底栏内层各加 `page-col`。
   ★★ **`page-col` 加在 `<main>` 上就一次性覆盖了所有页面** —— 比逐页改根容器少 8 处改动、
   风险也小得多。只有 `SettingsPage` / 作文本分支**不在 main 里**，要单独处理。
3. `SubHeader` 通栏 + 内层 `page-col`；**padding 仍留在 header 上** → 垂直尺寸一个像素不变。
4. 底栏 tab 加 `max-w-[7.5rem]` + 外层 `justify-center`（`flex-1` 在 1366 上会拉到 256px）。
5. `ui.tsx` 的底部弹层 → 平板上居中对话框（`md:items-center md:p-6`、`md:rounded-2xl`、
   抓手 `md:hidden`、`md:pt-5` 补留白）。
   ★★ 同时把遮罩从 `absolute inset-0` 改成 **`fixed inset-0`** —— 父级一加 `md:p-6`，
   `absolute` 就相对父级的 padding box 解析，四周露出一圈没盖住的地方。

**验证**：
- `npm run lint` → **0 error / 12 warning**（= 基线）
- `npx vitest run` → **45 files / 934 passed / 0 failed**（= 基线）
- 溢出：平板全档 **0**；报错 **0**。
- ★★ **手机档零变化的证明**用 A/B 做的：`git stash push -- src/` 之后重量 390，
  结果**逐项相同**（100% 列宽、同样 8px 溢出、同样点击区），`git stash pop` 复原。
