### ② 找到两个可能导致"很多都理解有问题"的原因

- **(a) 设置里的「本地引擎 / 远程 AI」是独立开关**（`SettingsPage` 两个 Chip）。
  `shouldUseRemote()` 要求 `mode === 'remote'` **且** baseUrl+apiKey+model 齐。

  而默认配置就是 `mode: 'local'`。这一族"改了设置没生效"本项目踩过好几次（见 §五/§七）。
- **(b) ★ 指令 schema 表达不了"相对指位"** —— 这是**结构性**的：
  `ParsedEditInstruction` 里 **只有 `replace-punct` 有 `near`**；
  `delete` 是 `{ target }`、`replace` 是 `{ from, to }`、`insert` 是 `{ anchor, position }`。
  于是孩子说「把玩篮球**后面的那个字**去掉」时，模型**没有字段可以表达"哪儿"**，
  只能二选一：猜一个字面量，或者按铁律返回 `unknown`。
  ➜ 表现就是「很多都理解有问题」。
  ★ 而执行层其实**已经有这套机器**（`applyEdit` 的 `replace-punct` 分支会
     `findAll(anchor)` 再按 `near` 定位）—— 缺的只是**把 `near` 推广到 delete/replace**。

## 九、实施「来源闸门」（家长说「Please continue」→ 按设计稿落地）

### 新文件 `src/domain/provenance.ts`

一个纯函数模块，**只做一件事**：判断"模型要写进去的字"有没有来源。

- `PUNCT_NAME_TO_SYMBOL` / `allowedPunctFrom(utterance)` —— 标点「名字→符号」白名单。
- `groundedInUtterance(span, utterance, allowed)` —— 子串判定。
- `MAX_SPAN_CHARS = 40` + `checkProvenance(intent, utterance)` 总入口。
- 越界返回 `{ ok: false, message }`，**不返回 unknown**。

接进 `parseEditInstruction`：`toInstruction` 之后、`return ok:true` 之前。
新增 `reason: 'invented'`。

### ★★ 标点白名单是这个模块**唯一必须开的口子**

孩子说「把句号改成叹号」，指令里带的是「**！**」——它**不是那句话的子串**。
照字面卡，「改标点」这一整类会被 **100% 挡在门外**，而那正是家长 09-20 亲口报过的需求。
放行**有条件的**：只有他**点过名的**标点才算"他说过的"（他说叹号 → 模型塞不进问号）。

### 记录面板：`原文 / 改成 / 你说`

- ★ 顺手把"哪儿变了"抽成 `diffBounds`，**`changedSpan` 和 `sentenceChange` 共用** ——
  两个函数各写一遍前缀/后缀循环就是 §四 那个老毛病（改一条忘一条 = 没改）。

### 踩到的两个坑（都是实测出来的，不是推的）

1. **`sentenceEnd` 要从 `to - 1` 起步，不是 `to`。**

## 十二、★★ 家长报「写作文 录音 好像有问题了。之前正常的」—— 查到根因并修掉

### 现象

家长原话：**「现在 写作文 录音 好像有问题了。 之前正常的。」**
「之前正常的」这句是关键线索 —— 说明是**回归**，不是功能没做。

### 排查顺序（都不是根因，但都验过，省得下次重走）

| 查了什么 | 结果 |
|---|---|
| 测试基线 | 32 files / 690 全绿 —— **测试绿不代表没坏**，这是运行时/存档问题 |

### ★★ 真正的根因：`engine` 字段是后加的，老存档被拼成**自相矛盾**的配置

`mergeSettings` 原本是这一行：

    transcribe: { ...defaultTranscribeConfig(), ...s.transcribe },

而 `defaultTranscribeConfig()` 后来从「整包上传（硅基流动）」**换成了**「火山流式」。
家长的存档是**加 `engine` 之前**配的硅基流动，里面没有 `engine`，于是合并成：

| 字段 | 值 | 来自 |
|---|---|---|
| `engine` | `'volcengine'` | 新默认值 ← **问题在这** |
| `apiKey` | `sk-fscrr…`（硅基流动的） | 老存档 |
| `baseUrl` | `https://api.siliconflow.cn/v1` | 老存档 |
| `model` | `Qwen/Qwen3-ASR-1.7B` | 老存档 |

两个判定**同时**说"能用"：`usesStreamingEngine()` 看 `engine`（真）、
`isTranscribeConfigured()` 看 `apiKey` 非空（真）→ 界面切成「按住说话」→
**拿硅基流动的密钥去连火山的 WebSocket** → 握手被拒 → 一个字都出不来。

而"之前"正是 `engine` 还不存在、走整包上传那条路的时候 → **完全对得上家长的描述**。

★ 这是 **MEMORY §七** 那一类病的**新实例**：「改了默认值 / 加了字段，老存档不跟着走」。
`ai` 那一路早就有了迁移（`migrateRetiredDeepSeekModel`），**`transcribe` 这路漏了**。

### 修法

**① `src/db/db.ts` 新增 `migrateTranscribeConfig(saved)`**，判据是
**「engine 必须和配置里其余字段自洽」**：

- **火山** ⇒ `baseUrl` **必须是空的**（火山那套不需要地址，默认就是空串）；
- **整包上传** ⇒ `baseUrl` 必须非空。

三条规则：
1. **老存档（没有 `engine`）** → 那时只有整包上传一条路，所以**有 `baseUrl` 就是 `openai`** ——
   绝不能拿新默认值的 `volcengine` 盖上去（这就是 bug 本身）。
2. **已经写坏的组合**（`engine` 说火山、却留着 `baseUrl`）→ 按密钥形状判归属：
   内置火山密钥是 UUID，`sk-` 开头的一定是另一家的 → 归回 `openai`；
   若密钥确实是内置火山 key，则只清掉残留的 `baseUrl`。
3. **家长自己填的、自洽的配置一律不碰**（同 §七 的规矩）。

**② `SettingsPage` 那个「火山」按钮也有同一个病**：
原本写的是 `apiKey: tr.apiKey.trim() || VOLC_TEST_API_KEY`
（"已经填过别的密钥就别覆盖"）—— 于是从硅基流动切到火山时，
**把硅基流动的 `sk-` 密钥带到了火山这条路上**，又造出一份自相矛盾的配置。
改成：**只有已经在这条路上时才保留密钥**，切过来时换成内置火山密钥。
