# 2026-09-19

## 一、改作文（语音编辑）「插入」缺失 —— 家长报的问题分析

家长原话：
> 「现在 改作文 有点问题。不够智能。感觉是限制太多。
>   比如 写的 是 小明 正在吃饭。录音 小明后面加 那个时候。 就处理不了。
>   你帮我分析下原因。是不是限制了。」

### 1.1 结论：不是「不够智能」，是**整类语法根本不存在**

`src/domain/voiceEdit.ts` 的 `EditIntent` 只有四种：
`replace` / `delete` / `append` / `undo`。
**没有 `insert`。** 所以「在 X 后面/前面/之间加 Y」这一整类说法
全部落到 `{kind:'unknown'}`。

探针实测（原文「小明正在吃饭。」）：

| 孩子说的 | 解析结果 |
|---|---|
| 小明后面加上那个时候 | ❌ unknown |
| 在小明后面加上那个时候 | ❌ unknown |
| 小明前面加上那个时候 | ❌ unknown |
| 小明和小刚之间加上那个时候 | ❌ unknown |
| 把那个时候加到小明后面 | ❌ unknown |
| **加上那个时候** | ✅ append |

### 1.2 更糟：认出来的那条也**放错位置**

`append` 的实现是**无条件接到正文末尾**：

```
「加上那个时候」 + 「小明正在吃饭。」 → 「小明正在吃饭。那个时候」
```

而孩子要的是 `小明那个时候正在吃饭`。
**所以即使命中，结果也是错的** —— 这条比 unknown 更危险，因为界面会报"加上啦！"。

### 1.3 为什么会写成这样：一条被**扩大解释**的约束

需求原文（文件头）：
> 「编辑的绝不允许 AI 帮改写。必须是小孩自己的能力。」

这条约束管的是**不许替孩子产出内容**（想词、润色、扩写）。
但实现把它一并套到了「**听懂孩子说的话**」上 —— 于是指令解析成了固定正则词表。

★ 关键区分：
- **不能碰** = 替孩子决定写什么（这条必须守死）
- **可以帮** = 听懂「把 A 改成 B」「在 A 后面加 B」（这只是解析指令）

`把A改成B` 和 `在A后面加B` 是**同一类事**，前者做了、后者没做。
所以这不是"底线"问题，是**覆盖不全**。

### 1.4 还有一条被忽略的降级

`VoiceComposer.tsx:242`：`useAiRevise = Boolean(ai && shouldUseRemote(ai))`。
**没配 AI 密钥就永远走本地正则**（DeepSeek 密钥至今没给）。
代码注释自己承认：「降级后会体现在效果上（听不懂带语气词的说法），这是已知代价」。

⚠️ 但**「配了 AI 就好了」是假出路**：AI 那条路是
`reviseEssay({text, instruction})` → 返回**改好的全文** `r.text`，
即**让模型产出正文** —— 这跟「不许 AI 帮改写」是直接冲突的。
反而本地那条不冲突。

### 1.5 其他真实限制（次要）

- **替换动词是固定词表**：`改成|换成|变成|…`。「小明叫做小刚」→ unknown。
- **目标必须逐字匹配**，ASR 错一个字就 `not-found`。
- 目标出现多次时停下问孩子（**这条是好设计，保留**）。
- `unknown` 时不猜、反问孩子（**也是好设计，保留**）。

### 1.6 建议修法（两层）

**第一层 —— 不需要 AI，最该做：**
给本地引擎加 `insert` 意图 + 位置锚点语法：
`X后面/前面/之间`、`在X后/前`、`把Y加到X后面`；
并把 `append` 语义收紧为「**没给锚点时才接到末尾**」。
这完全符合底线 —— 加进去的字是**孩子自己说的**。

**第二层 —— 可选：**
若要用 AI，正确用法是**只让它做意图解析**
（输出 `{kind, anchor, text}` 结构），**不产出正文**。
这样既听得懂口语，又守住「孩子指哪我们改哪」。

> 状态：**只做了分析，未改代码**（家长要的是"分析原因"）。
> 已用探针验证，探针文件已删。

## 二、改作文 —— 「不许 AI 帮写」落地（边界重划 + 实现）

家长看完上面的分析后，把边界重新划了一遍（**这是本次最重要的一句话**）：

> 「不许 AI 帮改写。**是 不许 AI 帮写。不是 不允许改写。**
>   比如小明正在吃饭，把正在后面的去掉，都是可以的。
>   小明后面加小红都可以。把小明改成大明都可以。
>   但**不允许 AI 自己生产内容**。类似 给这个句子加点比喻等等。都不行。
>   具体怎么限制 你处理。另外**已经设定了大模型**。」

### 2.1 分界线是「内容从哪来」，不是「谁在操作」

| | 允许 | 不允许 |
|---|---|---|
| 动作 | 换 / 删 / 挪位置 / 插 | 润色 / 扩写 / 加比喻 / 想结尾 |
| 判据 | 那些字是**孩子自己说的** | 内容是 **AI 造的** |

所以「AI 一个字都不许参与」是**读窄了**。AI 可以来"听懂"孩子说了什么。

### 2.2 旧 AI 路径本身就在违规

`ai.ts` 的 `reviseEssay({text, instruction})` 返回 **`r.text` = 改好的全文**。
提示词里写了"最小改动"，模型照样产出正文。
家长说"已经设定了大模型" ⇒ **这条路马上就是活的违规**。已整条删除。

### 2.3 ★ 落地手法：不靠提示词，靠**接口形状**

新增 `parseEditInstruction`，返回类型里**根本没有"正文"这个字段**：

```ts
export type ParsedEditInstruction =
  | { kind: 'replace'; from; to }
  | { kind: 'insert'; anchor; text; position }
  | { kind: 'delete'; target }
  | { kind: 'append'; text }
  | { kind: 'undo' }
  | { kind: 'refuse'; reason: 'content' }
```

模型想替孩子写都没有地方放。**这才是"不许帮写"在代码上的落地。**
`toInstruction()` 是最后一道闸门：不落在这六种形状里的一律当没听懂。

链路：孩子口语 → 模型只翻译 → **本地 `applyEdit` 执行** → 正文。

### 2.4 改动清单

- `voiceEdit.ts`
  - `EditIntent` 新增 `insert`（anchor/text/position）和 `refuse`。
  - 位置词常量 + `INSERT_VERBS`；3 条 `INSERT_PATTERNS`。
  - `parseEditIntent` 顺序重排：`undo → insert → append → delete → replace → refuse → unknown`
    - insert 必须早于 append（「小明后面加上那个时候」含「加上」）
    - refuse 必须**最后**（`replace` 指令里合法地含"优美/漂亮"）
  - `CONTENT_NOUN_ONLY` 单独一条：否则「加上一个比喻」会 append 字面四个字「一个比喻」。
  - `applyEdit` 新增 `insert` / `refuse` 分支，以及第 4 个参数 `by: 'child' | 'ai'`。
- `ai.ts`
  - 删 `REVISE_SYSTEM` / `buildReviseUserMessage` / `reviseEssay` / 两个旧 interface。
  - 新增 `PARSE_SYSTEM` + `buildParseUserMessage` + `toInstruction` + `parseEditInstruction`。
  - 抠不出 JSON / 形状不对 → 归 `unknown`（不归 `network`），诊断日志才不会把
    "模型乱回"记成"网络问题"。
- `types.ts`：`EditOperation.kind` 加 `'insert'`。
- `VoiceComposer.tsx`：拆成 `editLocally`（兜底）+ `editViaAi`（模型听懂→本地执行）。
  AI `unknown`/`network` → 退回本地；**AI `refuse` 绝不退回**（否则绕个弯又被执行）。
- `changedSpan` 已不在编辑链路上（只是还有测试在跑）—— 加了警示注释，
  它是"AI 返回全文"那个设计的配套工具，留着是个陷阱。

### 2.5 ★ 修 bug 时被测试抓出来的两个真问题

**① 「之后」被判成前插（意思说反，且不报错）**

判断前后用的是 `word.startsWith('后')`。「之后」以「之」开头 → 判成 `before`。
`之前` 反而因为「以'前'开头」为假而侥幸正确。
→ 改成查表 `AFTER_SET.has(word)`。**加词也不可能加错桶。**

**② 「X 和 Z 之间加上 Y」的锚点选谁**

原实现取 `anchor=Z, position='before'`。我第一版测试写成 `anchor=X, position='after'`，
两条断言打架。想清楚之后确认**实现是对的**：
`和` 是挂在第一个成分尾巴上的（「小明和」= "小明 and"），
所以两个名字中间的空档在 `和` 之后、第二个名字之前。
插到 `和` 前面会变成「小明那个时候和小刚」，更不通。→ 改测试，并把理由写进 pattern 注释。

## 三、评价页两处问题：思维导图偏位 + 评价内容不是 AI 分析的

家长原话（分两条报的）：

> 「评价里 作文长这样的 图 偏离了位置。没有靠左，
>   另外似乎 作文的结构 并不是AI分析的。评价里的东西 都需要 AI 分析。」
> 「还有更好的写法 也还是有问题。要结合 图 和 用户写的」

### 3.1 思维导图「偏离位置」—— 写死的 viewBox 和布局常量走了散

**探针实测**（渲染 markup，读 SVG 属性算边界）：

| | viewBox | 内容实际占的 x | 左留白 | 右留白 |
|---|---|---|---|---|
| 改前 | `0 0 360 H` | 62 … 352 | **62px** | **8px** |

内容明显偏右 —— 就是「偏离了位置，没有靠左」。

**根因**：布局常量（`CENTER_X=96` / `LEAF_X=262`）和**写死的 viewBox 宽度 360**
是**两份声明**。常量改了，360 不会跟着改，而且**不报任何错**。

**修法**：viewBox 由常量推出来 ——
`CONTENT_LEFT = CENTER_X - CENTER_W/2`、`CONTENT_RIGHT = LEAF_X - 4 + LEAF_W`、
`PAD_X = 12`，左右留白恒等。顺带把 rect 的 width 也改成引用同一份常量
（原来 `width="68"` / `width="94"` 是第三、第四份声明）。
另修了退化情况：没有分支时不能把"叶子那一列"算进内容宽度，否则图形缩在左边。

**验收**：`src/components/MindMap.test.tsx`（新文件）用
`renderToStaticMarkup` 读坐标算左右留白。**变异验证过**：把 viewBox 换回
`0 0 360 H`，测试立刻红并打印「左白 62 / 右白 8」—— 和探针数字完全一致。

### 3.2 ★★ 评价内容「不是 AI 分析的」—— 静默降级 + 假标记

**探针实测**：让模型只回 `dimensions + total + essayText`（其余全缺），
`scoreAndRewrite` 返回的 `score.engine` 仍是 `'remote'`（界面写「本次由远程 AI 评分」），
而这些字段全部来自**本地模板**：

| 字段 | 实际来源 | 有多离谱 |
|---|---|---|
| `summary` | 本地模板 | 写「你做到了 **61** 分」，而模型给的总分是 **85** —— 自相矛盾 |
| `strengths` | 本地模板 | 「用上了 1 个好词」 |
| `suggestions` | 本地模板 | 三条固定模板 |
| `mindMap` | 本地模板 | 「我的作文 · 真情实感最强」+「感官描写：视觉」 |
| `highlights` | 本地模板 | 甚至写「加了比喻和拟人」，而正文里根本没有 |
| `skeletonLines` | **本地那篇范文的骨架** | 和模型写的正文不是同一篇 |

最后一条尤其荒唐：背诵挑战会让孩子背的句子和看到的正文**对不上**。

**修法（两条纪律，写在 ai.ts 的 `scoreAndRewrite` 上方）**：

1. **缺项就补问一次**，而不是拿模板顶上。
   把模型上一次的原话 + 「你漏了 X，重发一份完整的」一起发回去。
   （只在"补出来的更全"时才采用，别把一份好的换差了；补问本身失败就吞掉，别让孩子白等。）
2. **补问还不行 → 评价整份退回本地**，并如实标 `engine: 'local'`。
   评价是**一个整体**，不能一半 AI 一半模板 —— 本地总评会带上本地算的分，
   和模型给的总分互相打架。宁可整份本地（界面会说"本地引擎"），也不要混着还说自己是 AI。
   ⚠️ 但**写法（essay）是另一个对象**，仍然保留 AI 那版（`essay.engine: 'remote'`）。

3. **骨架必须从模型自己那篇正文推**（`skeletonFromEssay` = `splitSentences` + `extractSkeleton`），
   模型没给也不许借本地范文的那一份。

**验收**：`ai.test.ts` 新增两组 describe（共 11 条）。**变异验证过两次**：
- 把骨架退回 `fallback.essay.skeletonLines` → 测试红，并打印
  「骨架「推开门的瞬间，校园整片扑了过来。」不在模型写的正文里」——正是那个串台 bug；
- 把补问去掉 → 3 条测试同时红。

## 四、「更好的写法」也还是有问题 —— 要结合 图 和 用户写的（第二次报）

家长原话：

> 「还有更好的写法 也还是有问题。 要结合 图 和 用户写的」

上一轮（09-18）已经按同一句话改过（把配图接进提示词 + 加「具体名物」抽取层），
所以这轮**不能再假设问题在素材层**。探针跑真实题库题 + 真实配图，逐句读输出。

### 4.1 真因：分类标签被当成了生成模板的依据

`prompts.ts` 的 `TOPIC_TAGS` 里，**「看图作文」的 category 是 `event`（写事）**：

```ts
{ id: 'look-picture', category: 'event', label: '看图作文', … }
```

于是孩子写《看图写话》，范文走的是**写事模板**，产出（实测，逐字）：

```
那件事发生在那天。那天的一切，我现在还能一件件说出来。
我最先注意到的是雪。我看了好久，舍不得挪开眼睛。
一开始我还没反应过来。一切发生得太快。接着，事情往前走，我的手心里全是汗。
周围有那么多声音，我却只听见自己的心跳。就在那时候，我想起了谁说过的一句话。
我和小明在雪地里打雪仗，还堆了一个雪人。……
```

加粗那三句跟图没关系、跟孩子写的也没关系 —— 它只是「一篇作文里该有的紧张感」。
**素材层抓得再准，也架不住中间段整段是模板编的。**

### 4.2 四处改动

| # | 文件 | 改了什么 |
|---|---|---|
| 1 | `modelEssay.ts` `resolveKind` | 加 `pictureFirst`：**写事模板必须有「事」**；`m.event` 为空且（有配图 或 有具体名物）→ 改走写景 |
| 2 | `modelEssay.ts` `extractConcrete` | ① 词表命中**不过泛称筛**（「雪人」里有个「人」，以前被整条丢掉）；② 量词兜底加谓词守卫（`CAPTURE_LOOKS_LIKE_PREDICATE`），挡掉「开满粉 / 小鸟飞 / 整整齐」 |
| 3 | `modelEssay.ts` `composeModelEssay` | 图注可以**补**孩子没写的地点/时间（只补空、不覆盖） |
| 4 | `scoring.ts` `extractSkeleton` | 叠词两道筛：已收走的叠词不再单收（AABB 被切成「安安/静静」）；叠字**名词**（`REDUP_NOUNS`：妈妈/星星…）不当修饰 |

词表补了 `雪地`、`飞机` 等（`飞机` 是因为新守卫里的 `飞` 会误伤它 —— **误伤的出路是加词表，不是放松守卫**）。

### 4.3 AI 那条路：跑偏守卫（一张清单，两处用）

上一轮只往提示词里加了配图，但**光把图发给模型，不等于它会照着写**。
实测它能把「写雪」改写成「推开窗，一片《春天的公园》扑面而来」，
而当时**照收不误**，界面上还写着「更好的写法」。

现在：`buildKeepList` 算一份「必须留住」清单，**同一份清单两处用** ——
写进提示词点名要求（`keepListSection`）+ 回来后照单核对（`offTopicWords`）。

- 判据刻意宽松：孩子清单非空 → 至少留住一条；孩子什么都没写 → 图里至少写进一条。
  「一条都没留住」才是没有争议的跑偏。
- 跑偏 → 带模型原话 + 点名丢了什么补问一次（`buildRetryNote` 现在分「缺字段」和「跑偏」两半说）。
- 还跑偏 → **写法退回本地**；**评价不牵连**（它是就孩子原文做的分析，跟改写跑没跑偏无关）。
- `generateModelEssay`（补生成那条路）同样加了这个守卫，
  并顺手修掉了它借本地范文 `highlights`/`skeletonLines` 的老毛病。

## 五、家长设置里的提示词，「更好的写法」也要落实（第三次报）

家长原话：

> 「可以的 很棒。 另外 更好的写法，还要结合下 家长设置里的 提示词。类似于点比喻之类的。」

### 5.1 真因（一句话）

`extraPrompt` 全项目只有**两个消费者**，都是 AI 提示词的拼装函数
（`ai.ts` 的 `buildEssayUserMessage` / `buildScoreAndRewriteUserMessage`）。
**本地引擎一个字都没读它。** 而设置页上写着「AI 点评和改范文时会参考这些要求」——
所以只要 AI 没配好、或调用失败降级到本地，家长写的「多用比喻」就被**静默丢弃**：
正文里没有比喻，亮点里也不提，界面上看不出任何异样。

### 5.2 ★ 第一版写完了，要求还是落不了地

代码写完了、`tsc -b --noEmit` 也过了，**但实测打出来要求一次都没落地**。
两个坑，都是「同一件事声明了两遍、只补了一处」：

| # | 现象（实测） | 真因 |
|---|---|---|
| 坑一 · 判早了 | 写景 + 家长点「通感」→ 正文和「没填」**一字不差** | `usedRhetoric` 算在**裁剪之前**的全量候选上。写景分支的候选里本来就带通感句（`我伸手碰了一下…`），于是引擎说「已经有了」→ 不补；可那句排在通用套话里、**随后被句数上限砍掉** → 两头落空 |
| 坑二 · 名额不够 | 一年级 + 家长点「比喻」→ 一次都没进去 | `keepCap` 确实加了 `+ demanded.length`，但**画面句不受 keepCap 约束地排在最前**（一年级 keepCap=3，画面句正好 3 句），家长那句永远排在画面句后面 |

修法：
- 修辞判定改成在 **`base`（裁剪之后真的留下来的那几句）** 上做；
- 家长点名的句子**不参与裁剪**，直接插在「画面句」之后、通用套话之前；
- `baseCap` 只用来裁 `[personHead, ...imagery, ...genericRest]` 这份候选。

优先级（`base` 的排序就是它）：① 写人时第一句是这个人 ② 画面句（「不跑偏」硬标准）
③ **家长点名的修辞** ④ 通用套话。家长要求**高于通用套话、低于画面句** ——
反过来就会退回第二轮那个「跟孩子写的和图都无关」的老毛病。

### 5.3 能做的做，做不到的说

- **能落实**（`demandSentences`）：比喻 / 拟人 / 通感 / 叠词。只补**还没出现**的那几样；
  句子一律锚在「那天」「我」上（补哪一句由"家长说了什么"决定，那里拿不到文体，锚名物会出病句）。
- **做不到**（`unfulfilledDemands`）：排比 / 对话描写 / 成语 / 首尾呼应 / 细节描写。
  在**降级警告**里如实点名（`withUnfulfilledNote` 包了 6 处本地兜底）。
  实测文案：
  > AI 设置里还缺密钥，先用了本地引擎。去设置页补全试试。**本地引擎做不到你在设置里要求的排比（那得按内容现写，模板拼不出来）。配好 AI 就会落实。**
- 两条纪律：① 本地引擎**真的做到了**的不在这里说（再警告一遍就是撒谎）；
  ② 一条要求都没填时不许平白多出一条警告。两条路（评分改写 / 补生成）口径一致。

### 5.4 亮点不再说假话

旧版 `buildHighlights` **无条件**写「加了比喻和拟人，让句子活起来」，
而写景 / 写事分支根本没有比喻 —— 家长想知道的正是「有没有落实」，
这条假话让他**永远看不出没落实**。

做法：四类修辞的模板数组（`SIMILE_TAILS` / `PERSONIFY_TAILS` / `SYNESTHESIA_BANK` /
`ADVERB_BANK` / `REDUP_ADJ_BANK`）**提到模块级**，生成句子的和判定「这篇到底用了哪些」
的 `usedRhetoric` 读**同一份**。亮点改成照实际产出说，并单独回一句
「家长点名的 X，都加进去了」。

### 5.5 设置页文案也改准了

改前只说「AI 点评和改范文时会参考这些要求」，没说哪几样在没配 AI 时也能落地 ——
家长没法据此判断该不该配。改成：

> AI 点评和改范文时会参考这些要求。**其中比喻、拟人、通感、叠词，本地引擎也会尽量落实；
> 排比、对话、成语这类要按内容现写，得配好 AI 才做得到。**不填就按默认标准来。

### 5.6 验证

- **变异验证（6 个守卫逐个破坏，写脚本批量跑）**：
  ① `parseExtraPrompt` 不解析 → 6 条红；
  ② 判定改回「裁剪之前」 → 坑一那条红；
  ③ 家长句重新参与裁剪 → 5 条红；
  ④ 亮点改回无条件宣称 → 假话那条红；
  ⑤ 降级时静默 → 3 条红；
  ⑥ 本地引擎收不到提示词 → 1 条红。
- `npm run lint` 0 error / 8 warning（基线）；`vitest` **582 passed | 10 skipped (592)，29 files**
  （原 577/29，+15 条：modelEssay +11、ai +5）。
- `npm run build` 成功（首次失败是 `safe-delete` 超时，`rm -rf dist` 后正常）。
- 打包产物核对：`家长点名的`=1、`本地引擎做不到你在设置里要求的`=1、`配好 AI 就会落实`=1、
  `都加进去了`=1、`句子活起来了`=1。
- 生成了 `settings-prompt-preview.html`（真因 + 两个坑 + 三组修复前后范文 + 亮点对照表 + 真实 toast 文案）。

### 5.7 已知遗留

- **AI 那条路没做「要求落实了没有」的校验。** AI 自由行文，我们的修辞指纹只认
  自己模板库里的句子（它写「像一根小鞭子」我们认不出），硬校验会**误报**。
  只把要求写进提示词（「逐条落实，判据是改写后的正文里真的找得到」）。

- 真机 + 真 DeepSeek 复验：家长的要求是否真的进提示词并落到正文里。
